- 取り組んだレベル：基礎
- やったこと（変更したファイル・設定・処理、または設計した取得方法）：`app/config.py`の`RAG_TOP_K`を既定値の5から1へ変更し、ベクトル検索で1ページだけを取得する条件にした。変更した箇所はこの設定値のみである。
- 比較した質問と、固定した条件（モデル・対象資料など）：質問は演習と同じ`第2回の説明では、LoRAは何を固定し何を学習しますか？ QLoRAは何を加えますか？`を使用した。モデルは`gemini-3.5-flash-lite`、対象資料は第1〜3回の本講義214ページ、実行方法は`uv run python -m app.agent --trace "$AIE_QUESTION"`で固定した。比較時に変更したのは`RAG_TOP_K=5`と`RAG_TOP_K=1`だけである。
- 結果（変更前後の回答・根拠、`--trace`の出力、時間・トークン数・生成API推定費用など）：変更前（`RAG_TOP_K=5`）は`search_materials({'query': 'LoRA QLoRA 固定 学習'})`を1回呼び、時間3.23秒、入力3,027／出力195トークン、モデル応答2回、推定費用0.001396 USDだった。回答はLoRAで元の重みを固定しA・Bを学習し、QLoRAで元の重みを4bit量子化することを正しく述べ、第2回PDF p.51・p.52を根拠にした。変更後（`RAG_TOP_K=1`）は`search_materials({'query': 'LoRA 固定 学習 QLoRA 加える'})`を1回呼び、検索結果には第2回の`lec02-main-p052`が入った。回答は同じく正しい内容で、第2回PDF p.52を根拠にした。時間は2.84秒、入力1,191／出力178トークン、モデル応答2回、推定費用0.000802 USDだった。
- 改善した例と、残る失敗・制約：変更後は取得ページ数を減らしたことで入力トークンが約60.7%、推定費用が約42.5%減少し、時間も約0.39秒短縮した。この質問はp.52に必要な説明がまとまっているため、RAG_TOP_Kを1にしても正答の根拠を失わなかった。一方、モデルが検索語を変えるため完全な再現性はなく、変更前後で検索語も異なった。また、Top-Kを減らすと複数ページが必要な質問では関連ページを取りこぼす可能性があり、今回の短い事実確認だけで一般的な優劣を断定できない。
- 気づき・疑問：関連する根拠が1ページに十分集まっている質問ではTop-Kを絞ることでコストと入力量を減せた。逆に複数回・複数章を比較する質問では、今回の1件のみの検索では根拠不足が起きる可能性があるため、Top-Kは質問の性質に応じて調整する必要があると考えられる。
