- 取り組んだレベル：発展
- やったこと（変更したファイル・設定・処理、または設計した取得方法）：
  - `app/retrieval.py` に `search_graph_multiquery` を追加した。複数論点の質問を独立した最大3つの検索語に分け、論点ごとにベクトル検索を実施し、各検索の上位ページをGraph探索の入口（seed）にする。
  - 既存の講義Graphを再利用し、`next_page` と `mentions` の辺を最大 `GRAPH_HOPS` まで幅優先でたどる。結果はページIDで重複排除し、同一ページが複数論点で見つかった場合は `facets` に該当論点をすべて記録する。seedとexpandedのページは重複させない。
  - データ形は既存のページJSONとGraph JSON（ページ・用語ノード、`next_page`・`mentions` 辺）を維持し、取得結果に検索論点、seed、展開ページ、hop数、経路を付ける。別資料にまたがるノイズを抑えつつ、質問の各論点を別々に検索したかったため、この設計にした。
  - `app/tools.py` にツール公開処理を追加し、`app/agent.py` のGraphモードでは比較・複合質問に複数論点検索を使うよう指示を変更した。`tests/test_search_graph_multiquery.py` にはAPIを呼ばないGraph fixtureのテストを追加した。また、 upstream との同期で現行ツール名とずれた `tests/test_adk_comparison.py` の期待値を更新した。
- 比較した質問と、固定した条件（モデル・対象資料など）：
  - 質問：「専門知識を追加したいとき、RAGとLoRA/QLoRAのどちらを選ぶべきですか？それぞれの利点と、選択の例外・判断条件を説明してください。」
  - 実際にGraphツールへ渡った検索論点：(1)「RAG LoRA QLoRA 選択 基準 利点」(2)「専門知識 追加 RAG LoRA QLoRA 違い」
  - 対象資料は第1〜3回。根拠候補として第2回 PDF p.47（知識追加ではRAGが有効になりやすいことと例外）、p.51–52（LoRA/QLoRAの仕組み）、p.58（Fine-Tuning前の判断項目）を資料JSONで事前確認した。
  - 条件：質問と資料範囲（第1〜3回）を固定し、同じ `gemini-3.5-flash-lite` で比較した。基本RAGは通常モードの `search_materials`、提案方式は `--graph` の論点別Graph検索。
- 結果（変更前後の回答・根拠、`--trace`の出力、時間・トークン数・生成API推定費用など）：
  - 基本RAGの回答要旨：知識追加にはRAGが有効になりやすく、LoRA/QLoRAは少量の差分だけを学習する方法として説明。例外として、継続事前学習（CPT）、多様な言い換え例を使うFine-Tuning、振る舞い調整を挙げた。回答中の根拠は第2回PDF p.47、p.51–52。
  - Graph回答の要旨：知識の更新・最新性が必要ならRAG、出力形式・口調・手順など振る舞いを変えたいならLoRA/QLoRAという判断を提示。CPTを使える大量コーパス、評価セットの準備、まずプロンプト/RAGを試す条件も説明した。回答は第2回PDF p.46–53を中心に引用した。
  - `--trace`：基本RAGは `search_materials(query='RAG LoRA QLoRA 専門知識')` を1回。発展Graphは `search_graph_multiquery` を1回呼び、queries は `['RAG LoRA QLoRA 選択 基準 利点', '専門知識 追加 RAG LoRA QLoRA 違い']`。ツール内では各論点を別々にベクトル検索した。
  - 取得ページ：基本RAGの上位5件は第2回PDF p.47、p.52、p.24、p.51、第2回PDF p.6。発展Graphはseed 3件（p.52、p.47、p.51）と展開7件（p.53、p.46、p.48、p.50、p.45、p.49、p.14）で、重複なし。章・ページは同じ第2回資料内。

- 改善した例と、残る失敗・制約：
  - 改善例：基本RAGでも主要ページp.47・p.51–52を取得したが、GraphはCPT（p.48）、LoRAの役割（p.46）、Finetuning判断手順（p.50）、実施モデルの選び方（p.45）など隣接する判断材料を追加でき、複合質問への説明範囲を広げた。
  - 失敗例：Graph回答はRAGの最新性・情報源提示の説明に第2回PDF p.27–28を引用したが、実際に返されたseed/expanded一覧にp.27–28は含まれていなかった。取得根拠から外れた引用であり、検索拡張を増やしても回答の根拠対応は保証されない。また、p.14のように今回の判断には直接不要と思われる候補も取得した。
  - 制約：複数論点の分解と回答はモデルに依存し、Graphの辺にないページは拾えない。API・モデル状態によっては503が発生し、同じモデルで再試行が必要だった。今回は初回のGraph生成が503で失敗し、待機後の成功実行を計測対象にした。性能・費用比較は各方式1回のみ。
  - 追加したGraph動作テストはCodespaceで `uv run pytest -q tests/test_search_graph_multiquery.py` を実行し、5件すべて成功。旧ツール名を期待していたテストを現行の `search_materials` / `make_quiz` に合わせた後、全テストスイートは35件すべて成功。
