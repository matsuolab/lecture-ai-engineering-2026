  - `uv run python -m app.retrieval "LoRA QLoRA 違い"` の上位5件は、第2回 p.52（LoRAとQLoRA）、p.51（PEFT）、p.60（今日の演習：QLoRA）、p.47（知識の追加はRAGが効きやすい）、p.61（演習の進め方）

- 取得した情報が足りなかった例、取得できたのに回答へ使えなかった例：
  - **取得できたのに使えなかった例**：全文投入のQ1。p.51・p.52の場所は正しく示したのに、答えを書かず「考えてみてください」で終わった。指示文の「宿題の答えそのものは書かず、考え方のヒントで導く」を、講義内容の質問にも当てはめたためとみられる。入力上限のエラーではなく、入力できたうえで根拠を回答に使わなかった現象として記録する。同じ指示文を持つほかの3方式は正しく答えたので、11万トークンの中で質問と指示の優先度を誤った可能性がある
  - **足りなかった例**：Q2のTreeとGraphは、確認する根拠に挙がっているp.13（メモリの章の導入）を引用しなかった。ただしp.39・40だけで回答は成立していた
  - **不要な情報が混ざった例**：Q2のTreeはp.41（Skill）を、ベクトル検索はp.65（補足）を取得した。ベクトル検索はp.65も引用したが、内容は誤りではなく補足として使えていた
- 今回の用途に採用したい方式と、その理由・比較条件の限界：
  - **ベクトル検索を基本にする**。Q1・Q2ともに正しく、時間（約3〜4秒）・入力トークン（約2.5〜3千）・費用がいちばん少なかった。Q2では必要な3ページをすべて1回の検索で取得できた
  - Treeは目次をたどる過程がtraceで追いやすく、根拠を説明しやすい。ただしモデル応答回数が5〜7回と多く、トークンは3〜4倍、時間は2〜3倍かかり、章をまたぐ根拠（p.13）は取りこぼした
  - Graphは前後ページの文脈を増やせるが、今回の質問では入口だけで足りたので、入力トークンが増えたぶんの効果は見えにくかった
  - 全文投入は約11.7万トークン・247秒かかり、しかも答えを返さなかった
  - 限界：各質問1回だけの実行で、モデルの出力は毎回変わる。全文投入だけ対象資料が9資料・438ページと広い。Q3は同時実行の影響で時間が大きく出ており、時間の比較には使えない
- 気づき・疑問：
  - 「答えの場所を知っている」ことと「答えを書く」ことは別だと分かった。全文投入の失敗は取得ではなく指示の解釈で起きており、traceがないと原因の切り分けが難しい
  - 検索語はモデルが質問から自動で組み立てていた。Q2で「第3回」まで検索語に入れていたが、ベクトル検索でこの語がどれだけ効いているかは分からない
  - Graphのtraceはツールの戻り値が途中で切れるので、expandedにどのページが入ったかを確認するには別の表示が必要だと感じた
  - 疑問：講義内容の質問と宿題の答えを、指示文だけでどこまで区別させられるか
