- 検索だけを実行して見つかったページと、その本文で確認できたこと：  `uv run python -m app.retrieval "LoRA QLoRA 違い"`を実行した結果、検索順位1位が第2回p.52、2位がp.51だった。p.52には、元の重みWを固定して小さな行列A・Bを学習するLoRAと、元の重みを4bitに圧縮するQLoRAが説明されていた。3〜5位にはp.60、p.47、p.61が取得されたが、今回の質問ではp.51〜52で必要な根拠がそろっていた。

- `--trace`で見えたツール呼び出し（ツール名・引数・回数、Treeでたどった目次など）：
  全文投入では検索ツールを使用せず、モデル応答は1回。
  ベクトル検索では`search_materials`を1回呼び出し、検索語は「LoRA QLoRA 固定 学習 第2回」だった。モデル応答は2回。
  Treeでは`browse_tree`を4回呼び出し、講義一覧→第2回→「選んだモデルを、いつ・どう直すか」→p.52の順に探索した。モデル応答は5回。
  Graphでは`search_graph`を1回呼び出し、検索語は「LoRA QLoRA 固定 学習」だった。モデル応答は2回。追加取得ページの詳細は省略表示のため確認できなかった。

- 取得した情報が足りなかった例、取得できたのに回答へ使えなかった例： 
全文投入では、正しい参照ページを提示できたものの、質問に対する具体的な回答を生成しなかった。必要な情報が入力内に存在していても、回答へ適切に利用されるとは限らない例であった。
  一方、今回の基本RAGでは必要な根拠を取得して、正しく回答した。根拠情報が取得できなかった失敗例は今回の質問では確認されなかった。

- 今回の用途に採用したい方式と、その理由・比較条件の限界：
  今回の質問では、回答精度を維持しながら入力トークン数とAPI推定費用を最も小さくできた基本RAGを採用したい方式です。
  Graphは処理時間が最短だったが、入力トークン数と費用は基本RAGより多かった。
  
- 気づき・疑問：
  必要な情報を大量に入力することと、その情報を正しく利用できることは異なると実感した。
  基本RAGでは必要なページを選択することで、回答精度と処理効率を両立できたと思う。
  一方、複数ページや複数章にまたがる質問ではTreeやGraphが有効になる可能性があり、質問の性質によって検索方式を選択することが重要だと考えます。
