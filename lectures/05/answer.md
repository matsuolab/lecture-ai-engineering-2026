### やったこと（変更したファイル・設定・処理）

**基礎：`RAG_TOP_K` を 5 → 10 に変える（1か所だけ）**

- `app/config.py` の `RAG_TOP_K` を環境変数 `AIE_RAG_TOP_K` で上書きできるようにした（既定は 5 のまま）。`AIE_RAG_TOP_K=10 uv run python -m app.agent --trace "…"` で変更後を試せる
- 指示文・ツールの説明・ツール名は変えていない

**実装：検索結果に前後1ページの本文を付ける（`--neighbors`）**

- `app/retrieval.py` に `add_neighbor_pages(hits, pages, window=1)` と `search_with_neighbors(query)` を追加
  - 前後は **同じ資料（`document_id`）の中だけ** で探す。第1回の最終ページの「次」に第2回の p.1 を付けない
  - **同じページは1回だけ** 返す。上位のページが別の hit の前後としても出るときは `role: "hit"`（距離・順位付き）として扱う
  - 並びは検索順位を保ち、各 hit ごとに「前 → hit → 後」。前後で足したページは `role: "neighbor"`・`neighbor_of`（どの hit の前後か）を持つ
- `app/tools.py` に `search_materials_with_neighbors` を追加。`app/agent.py` ではこれを **ツール名 `search_materials` のまま** 登録し（`NEIGHBOR_TOOL`）、`--neighbors` で切り替える。INSTRUCTIONS は通常の検索と同じ。説明文には「role が hit / neighbor の意味」の1行だけを足した
- `--trace` の `search_materials` の戻り値を「`7ページ・本文3,305文字: 第2回 p.51（前後）、第2回 p.52 …`」の形で表示するようにした（モデルへの入力は変わらない）
- `uv run python -m app.retrieval --neighbors "LoRA QLoRA 違い"` で、検索だけの結果も前後付きで確認できる
- テスト：`tests/test_neighbors.py`（資料をまたがない・重複しない・hit を優先・資料の端・window=0、ツール名が同じまま結果がモデルに届くこと）、`tests/test_lec05_homework_script.py`（比較スクリプトを API なしで最後まで通す）。`uv run pytest -q` で全件 pass

**比較のしかた**

- `scripts/run_lec05_homework.py` で、同じ質問を「通常（top5）／基礎（top10）／実装（top5＋前後）」の3方式で実行し、`lectures/05/results/homework_report.md`・`homework_runs.json` に回答・`--trace` の表示・取得ページ・時間・トークン数・推定費用を保存した
- 検索だけの比較は、質問文をそのまま検索語にして **埋め込みを1回だけ** 呼び、その上位10件から top5・top10・top5＋前後を作った（埋め込みの揺れが比較に混ざらないようにするため）
