# 第4回 基礎・実装の進め方

まだ本物のモデルで実行した結果は含まれていません。APIキーは前回のCodespaces設定を使います。

## 1. 配置

第3回の実装があるCodespacesで、リポジトリ直下にZIPを置きます。解凍は不要です。

```bash
git switch -c lec04-homework
python lec04_homework.zip install
uv sync
```

ブランチが既にある場合だけ `git switch lec04-homework`。既存ファイルが異なる場合、インストーラーは上書きせず停止します。

## 2. 作問と回答生成

`data/eval/my_cases.jsonl` に10問を用意しています。作問モードと同じ形式を直接作成しました。質問と期待するふるまいを読み、必要なら自分の関心に合わせて修正してください。参照idは `data/glossary.json` にあるものを使います。

```bash
uv run python scripts/run_lec04_homework.py generate
```

前回の自分のagentを使い10件の回答を生成します。メモ保存の承認が出た場合は内容を確認して判断してください。回答と実行メッセージを保存します。API制限エラーが出たら表示を共有してください。

## 3. 人のラベルを付ける

次を1つずつ実行します。各質問の回答・参照・期待するふるまいを読み、5基準それぞれ `y`（合格）または `n`（不合格）→Enter。中断しても保存済みの質問は飛ばします。

```bash
uv run python scripts/run_lec04_homework.py label-basic
uv run python scripts/run_lec04_homework.py label-my
```

- 根拠：参照に矛盾せず、不明なことを断定していないか。
- 範囲：講座の質問に対応し、講座外・役割変更要求を断っているか。
- ヒント：宿題の完成解答を渡していないか。宿題以外は合格。
- 分かりやすさ：直接・簡潔で繰り返しが少ないか。正しさとは別に評価。
- 回の表示：最後の非空行に「第N回」があるか。

曖昧な場合も仮の合否を選び「迷った」をyにして理由を記録します。AIが付けたラベルを自分の判定として使わないでください。

授業と同じ画面でも可：

```bash
uv run --with streamlit==1.66.1 streamlit run tools/annotate.py
```

ポート8501を開き、実装のラベル時は評価セットを `data/eval/my_cases.jsonl`、保存先を `lectures/04/my_labels.jsonl` に変更。セットを切り替えたらブラウザーを再読み込みしてください。作問モードで既存10問を確認できます。

## 4. 3条件を採点

```bash
uv run python scripts/run_lec04_homework.py grade
```

基礎の前後は同じ講師作成の10回答・同じ人手ラベル・同じモデル・同じ判定順で比較。変更はrubricの「用語集にないと明示した一般説明をpassとする」方針だけです。実装10回答は変更後基準で採点します。実測入力のコピーとハッシュを保存します。途中でAPI制限になったら1分以上待ち同じコマンドで再開できます（完了済み条件を再利用）。1条件内で失敗した場合その条件はやり直します。

`--model test` は動作確認用で本番結果と別フォルダに保存。提出用の実測として扱いません。

## 5. 分析・提出

`lec04_results.zip` を右クリック→ダウンロードし、チャットへ添付してください。`lectures/04/homework_report.md` は実測値を埋めた下書きです。不一致の意味を一緒に確認し、本人の気づきを加えてから `lectures/04/answer.md` の宿題欄に入れます。既存の演習欄は残します。answer.mdがなければ新規作成します。

提出対象：今回のコード、10問と回答、人手ラベル、前後の採点基準、resultsの実測記録、完成したanswer.md。ZIP自体と下書きは不要です。mainへの反映は自分のfork宛てのPRで行います。

## 読み方

一致率は「採点器が人に同意した割合」で、エージェントの正答率ではありません。unsureは分母から外れるので、要確認項目数・質問数・coverageも見ます。10問・各条件1回の観察から一般的な優劣は断定しません。
