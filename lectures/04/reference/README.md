# 第4回 参考資料

- `labels_instructor.jsonl`：講師が付けたラベルです。`note` に、その項目をどう判定したかと、わざと混ぜた失敗の説明を書いてあります。
  講師のラベルが正解というわけではありません。人同士でも割れる項目があることを見るためのものです。

自分のラベル（`lectures/04/labels.jsonl`）と比べるには、`tools/annotate.py` の「比べる」画面か、次のコマンドを使います。

```bash
uv run python -m app.judge --compare lectures/04/reference/labels_instructor.jsonl
```

## 本番の採点（gemini-3.5-flash-lite）で分かったこと

講師ラベルを「自分のラベル」として `app.judge` を流した結果と、そこから `rubric.md` と評価セットに入れた直しです。

| 見られたこと | 直したこと |
|---|---|
| #02 根拠：参照の「期待するふるまい」に書いてあった「末尾に第3回を示す」を理由に fail にした（回の表示はコードで判定する） | 「期待するふるまい」から「末尾に第N回を示す」を外し、rubric.md に「末尾の第N回はここでは判定に含めない」を追記 |
| #06・#08 分かりやすさ：ヒントや範囲で fail にした理由を、分かりやすさにも持ち込んで fail にした | rubric.md の分かりやすさに「読みやすさだけを見る。内容や役割は他の基準で見る」を追記し、採点のしかたに「基準は独立に見る」を追記 |
| #04 分かりやすさ：同じ説明を繰り返す冗長な回答を pass にした | 「同じ内容の言い換えや繰り返し（例：「つまり」で同じ説明をまとめ直す）は fail」と具体化 |
| #05 根拠：unsure ではなく pass を出した（基準に書いていない論点を自分で決めてしまう） | rubric.md の最後に「まだ決めていないこと」の欄を作り、当てはまる回答は unsure にすると明記。STEP 3 では、ここにある論点を決めて基準に書き足す |

採点のモデルは、基準に書いていない論点でも pass / fail を決めてしまう傾向があります。授業の前に、直した rubric.md でもう一度流して、#05 が unsure になるかを確認してください。
