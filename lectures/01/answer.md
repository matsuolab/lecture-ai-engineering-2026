## 宿題
-  取り組んだレベル：基礎 
- やったこと：環境変数 `AIE_MODEL` でモデルを切り替え、同じ質問「LoRAとは何ですか？」を実行した（成功3回、失敗2回）。

- 結果：
  | モデル指定 | 結果 | 入力 / 出力トークン |
  |---|---|---|
  | gemini-3.5-flash | 成功 | 7 / 667 |
  | gemini-3.8-flash | 成功 | 7 / 749 |
  | gemini2.5-flash（ハイフン抜け） | 404エラー（モデルが存在しない） | - |
  | gemini-3.5-flash lite（スペース混入） | bashエラー（`lite: command not found`） | - |

  - 成功した3モデルとも「LoRA = Low-Rank Adaptation、元のモデルを固定して差分だけを学習する技術」という核心は正しく答えた。
  - 3モデルとも「辞書に付箋を貼る」というたとえを使い、メリット（軽量・省メモリ・着脱可能）や用途（画像生成・LLM）の構成もほぼ同じだった。
  - 違いは細部に出た。
    - 3.5-flash：Microsoft・2021年に言及。
    - 3.8-flash：行列の低ランク分解という仕組みまで説明し、通信規格の「LoRa」との区別も補足した。ただし「ローダブル・低ランク適応」という誤った和訳があった。
    - 3.5-flash-lite：Microsoft・2021年への言及がなく、「小さう」という誤字があった。

- 気づき・疑問：
  - 気づき1：入力トークンが全モデルで7。質問文だけが送られており、システムプロンプトも会話履歴もない「素のLLM」であることが数字からも確認できた。
  - 気づき2：バージョンが新しい（3.8）からといって、必ずしも正確とは限らない。「ローダブル」という誤訳があった。一方、lite版は情報量が少なく誤字もあった。ただし各1回の試行なので、モデルの優劣とは言い切れない。
