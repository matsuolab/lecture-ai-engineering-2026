## 宿題

- 取り組んだレベル：実装
- やったこと：
  - `app/ask.py` に `--chat` オプションを追加し、会話履歴を保ったまま続けて質問できるようにした（`uv run python -m app.ask --chat`。空行か `exit` で終了）
  - `Conversation` クラスが履歴を `types.Content` のリスト（`user` と `model` が交互）で持ち、質問のたびに「これまでの履歴＋今回の質問」をまとめて `generate_content` に送る
  - API 呼び出しが失敗したターン（レート制限など）は履歴に足さない。足すと `user` が2回続く履歴になるため。失敗しても会話は終わらず、同じ質問を送り直せる
  - 第1回演習のトークン数表示は `print_usage()` にまとめ、1回だけの質問と会話モードの両方で使うようにした
  - API キーなしで動くテスト `tests/test_ask.py` を追加した。送られた `contents` を記録する偽のクライアントを使い、2回目の呼び出しに1回目の質問と応答が含まれること、失敗したターンが履歴に残らないことを確かめている

- 気づき・疑問：
  - LLM の API は呼び出しごとに状態を持たないので、「会話を覚えている」ように見えるのは、クライアント側が履歴を毎回送り直しているから
  - そのため、ターンが進むほど入力トークン数が増え、料金や無料枠の消費、応答時間も増えていく。長い会話では、古い履歴を捨てる・要約するなどの工夫が必要になりそう
  - `google-genai` には履歴を自動で管理する `client.chats.create()` もあるが、今回は仕組みを確かめるため、履歴を自分で組み立てた
