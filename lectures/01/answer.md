# 第1回 解答

## 演習

- 講座に固有の質問（宿題の3レベル）へのモデルの回答（要約でよい）：AIE2026の具体的な講座内容を把握していないことを示唆しつつ、一般的なプログラミング教育における初級・中級・上級の3段階として回答した。
- 用語集の正しい意味と比べて気づいたこと：用語集では、宿題の3レベルは「基礎（モデルの回答比較）」「実装（会話履歴を保持した連続質問）」「発展（応答時間とトークン数の比較）」と定義されている。一方、Geminiは一般的なプログラミング課題の難易度として説明しており、具体的な内容は一致しなかった。講座固有の情報を持たないLLMは、一般的な知識からもっともらしい回答を生成することがあると分かった。
- 表示できたトークン数（入力 / 出力）：21／543

## 宿題

### 基礎レベル

- 取り組んだレベル：基礎
- やったこと：
  - LoRAについて同じ質問を複数回実施し、回答内容の違いを比較した。
  - 使用モデル：
    - `gemini-3.5-flash-lite`
    - `gemini-3.8-flash`
  - 環境変数 `AIE_MODEL` でモデルを切り替えた。
  - temperatureは明示的に変更していない。

- 結果：
  - 軽量モデルでは3回の実行すべてに成功し、出力トークン数は597、584、641だった。
  - 上位モデルでは2回の実行に成功し、出力トークン数は706、746だった。
  - 上位モデルの3回目は60秒でタイムアウトした。
  - 同じ質問でも回答内容や文章量に違いがあり、上位モデルでは応答遅延も観察された。

- 気づき・疑問：
  - **同一モデルによる回答の違い**
    - 同じ質問でも、出力トークン数や説明内容に違いが生じた。
    - 一方で、LoRAの基本的な定義や、元モデルを固定して少数の追加パラメータを学習するという説明は概ね共通していた。
    - 一部の回答では同じ説明が繰り返されており、回答が長いほど品質が高いとは限らないことが分かった。

  - **モデル間の回答内容の比較**
    - 上位モデルの回答には、LoRAが提案された時期や行列分解の仕組みなど、より技術的な説明が含まれていた。
    - ただし、試行回数が少ないため、今回の結果だけでモデルの優劣を断定することはできない。

  - **応答時間とAPIの安定性**
    - 軽量モデルは正常に動作し、時間計測を行った実行では約3.8秒で回答した。
    - 一方、上位モデルでは回答待ちが長くなり、60秒でタイムアウトした。
    - APIの利用制限、自動再試行、モデルの処理負荷などが原因として考えられるが、今回の実験では原因を特定できなかった。

  - **今回の実験から学んだこと**
    - LLMの評価では、回答の正確性だけでなく、出力の安定性、応答速度、トークン数なども考慮する必要があると感じた。

### 実装レベル

- 取り組んだレベル：実装
- やったこと：
  - GitHub CopilotのAgentモードを使用し、`app/ask.py` に会話履歴を保持した連続対話機能を追加した。
  - `--chat` オプションを追加し、同一チャットセッションで複数の質問を実行できるようにした。
  - 既存の1問1答機能を維持した。
  - テストコードを追加し、自動テストを実施した。

- 結果：
  - `uv run pytest -q` を実行し、21件すべてのテストが成功した（3.87秒）。
  - Gemini APIを使用して、以下の連続対話テストを実施した。

  | 質問 | 入力トークン | 出力トークン |
  |---|---:|---:|
  | LoRAとは何ですか？ | 7 | 586 |
  | それとQLoRAの違いは何ですか？ | 604 | 647 |
  | 今の説明を一文でまとめてください。 | 1261 | 36 |

  - 3回目の質問では、それまでのLoRAとQLoRAに関する説明を踏まえた要約が生成され、会話履歴が保持されていることを確認できた。

- 気づき・疑問：
  - 会話履歴を保持することで、前の質問を踏まえた連続的な質問応答が可能になった。
  - 入力トークン数が7→604→1261と増加したことから、過去の会話内容が次のリクエストに含まれていると考えられる。
  - 会話履歴の蓄積は利便性を高める一方で、APIのトークン使用量の増加につながることを理解した。
  - GitHub CopilotのAgentモードを利用し、コードの実装からテストまでを支援させる開発手法を経験できた。
  - AIが生成したコードについても、人間によるレビューと動作確認が重要だと理解した。
