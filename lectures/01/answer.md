## 宿題

- 取り組んだレベル：実装
- やったこと：Copilotに依頼して、`app/ask.py` を改修し、最初の質問と続けて入力した質問を同じ Gemini Chat に送るようにした。回答後に次の質問を入力でき、空行または `exit` や `quit` で終了する。元の実装では `generate_content()` を毎回呼び出していて、前の質問が履歴として残らないため、同じ話題を続けて聞くことができなかった。そこで `client.chats.create(model=MODEL)` で 1 つの会話セッションを作り、`ask(chat, question)` のように同じ `chat` を引数として受け取り、`chat.send_message(question)` で送信するようにした。これで直前の文脈が次の質問に含まれ、会話の継続が可能になる。
- 結果：追質問でも同じ Chat が使われることをテストで確認した。
- 気づき・疑問：会話が長くなるほど履歴のトークン数が増えるため、コンテキストウィンドウや利用上限への配慮が必要になる。特に、長い会話を続けるとトークン数が増えて、回答が制約される可能性がある。


- 取り組んだレベル：基礎 
- やったこと：temperatureの値を0.2と1.0に変えて、以下のプロンプトを3回ずつ実行し、出力の違いを観察した。
「雨の日だけ開く喫茶店の名前を、理由付きで3つ考えてください。」
また、ターミナルにtemperatureの値を表示するようにcopilotに依頼し、実行した。モデルはgemini-3.5-flash-liteを使用している。
- 結果：temperature=0.2の場合は、「喫茶」「珈琲」といった喫茶店を表すような単語と「雨」「曇」「しずく」といった雨を直接的に連想させるような単語の組み合わせが多かった。一方で、temperature=1.0の場合は、「ペトリコール」「長靴と銀の匙」「雨宿り文庫」など、喫茶店や雨からは直接的に連想できないような単語を含んだ店名も出力した。
- 気づき・疑問：temperatureの値が大きい方が、確率的に低い（レアな）言葉が出力されることがわかった。理由の箇所を読んでも、temperatureの値が大きい場合は詩的な表現が多くオリジナリティに富んでいるように感じた。普段、わからないことを聞いたり、コーディングを手伝ってもらうときにはtemperatureは低くてよいと思うが、このような創作的なタスクに取り組む場合（画像生成など）は、temperatureを高く設定するとよいのではないかと考える。

- 取り組んだレベル：発展
- やったこと：`app/ask.py` に応答時間と入力・出力トークン数の表示を追加した。比較実験では会話履歴の影響を避けるため Gemini API の `generate_content` を使い、同じ3種類の質問を `gemini-3.5-flash-lite` と `gemini-3.5-flash` に各2回ずつ送った。質問は「LoRAを一文で説明」「temperatureの用途と注意点を説明」「雨の日だけ開く喫茶店の名前を理由付きで3つ提案」。条件は temperature=0.2、出力上限512トークン、思考レベル MINIMAL とし、各リクエストを独立して実行した。応答時間は送信から回答受信までを計測した。
- 結果：実測値は次のとおり（時間は秒、トークンは入力／出力）。同じ質問の入力トークン数はモデル間で同じだった。

| モデル | 質問 | 入力トークン | 出力トークン（1回目 / 2回目） | 応答時間（1回目 / 2回目） |
|---|---|---:|---:|---:|
| gemini-3.5-flash-lite | 短い知識質問 | 9 | 46 / 48 | 1.025 / 0.883 |
| gemini-3.5-flash-lite | 説明質問 | 22 | 261 / 256 | 2.070 / 1.592 |
| gemini-3.5-flash-lite | 創作質問 | 20 | 499 / 371 | 2.997 / 2.571 |
| gemini-3.5-flash | 短い知識質問 | 9 | 52 / 55 | 21.897 / 4.127 |
| gemini-3.5-flash | 説明質問 | 22 | 349 / 425 | 6.080 / 6.174 |
| gemini-3.5-flash | 創作質問 | 20 | 682 / 508 | 6.936 / 5.302 |

2回の平均応答時間は、flash-lite が短い知識質問0.954秒・説明質問1.831秒・創作質問2.784秒、flash がそれぞれ13.012秒・6.127秒・6.119秒だった。flash の短い知識質問は1回目が21.897秒、2回目が4.127秒と大きく異なり、初回を含む平均が外れ値の影響を強く受けている。この2回だけの結果では、flash-lite の応答が一貫して速かったものの、モデル一般の速度差とは断定できない。回答の出力トークン数は質問が長いほど増える傾向があり、同じ質問でもモデルや試行によって変化した。flash の創作質問は2回とも API が `MAX_TOKENS` を返しており、上限で回答が終了したため、この出力トークン数や応答内容の比較には注意が必要である。
- 気づき・疑問：応答時間はモデルの違いだけでなく、通信やサービスの混雑、初回処理などの影響も受ける。2回では十分な比較にならないため、より確かな評価には同じ条件で回数を増やし、平均だけでなく中央値も確認する必要がある。また、トークン数は回答の長さを表す一つの目安だが、回答の正確さや質そのものを示すわけではない。今回の測定は2026年10月26日に行った実行環境での結果であり、利用時期や環境が変われば値も変わる。
