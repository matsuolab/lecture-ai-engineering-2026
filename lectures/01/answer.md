## 宿題

- **取り組んだレベル：実装**

- **やったこと：**

  `app/ask.py`を改修し、会話履歴を保持したまま複数の質問を続けて実行できる機能を追加した。

  主な変更内容は以下のとおりである。

  1. `--chat`オプションを追加し、単発質問モードと連続質問モードを切り替えられるようにした。
  2. 連続質問モードでは、同じチャットセッション内で過去の発言を保持し、後続の質問に文脈を引き継げるようにした。
  3. ターミナルから質問を繰り返し入力できる対話形式のインターフェースを追加した。
  4. `/exit`などの終了操作によって会話を終了できるようにした。
  5. APIの応答から入力トークン数と出力トークン数を取得し、表示できるようにした。

  実装後、以下のコマンドで動作を確認した。

  `uv run python -m app.ask --chat`

- **結果：**

  会話履歴が正しく保持されているか確認するため、次の2つの質問を連続して実行した。

  **質問1：** 私の好きな果物はみかんです。

  **AIの回答：** みかんについての感想や追加の質問を含む回答が生成された。

  **質問2：** 私の好きな果物は何ですか？

  **AIの回答：** 「あなたの好きな果物は『みかん』です！」と回答し、直前の会話で伝えた情報を参照できた。

  それぞれのトークン使用量は以下のとおりであった。

  | 会話 | 入力トークン数 | 出力トークン数 |
  |---|---:|---:|
  | 質問1 | 9 | 86 |
  | 質問2 | 104 | 20 |

  2回目の質問では、質問文自体は短いにもかかわらず入力トークン数が増加しており、会話履歴がモデルに渡されていることと整合的な結果になった。

  また、`/exit`による会話終了と、従来の単発質問モードによる回答生成も確認した。

  最後に`uv run pytest -q`を実行した結果、**11件すべてのテストが成功した（11 passed in 3.74s）**。

- **気づき・疑問：**

  今回の実装を通じて、単発質問と連続質問の違いを理解できた。連続質問では、モデルが前の発言を利用できるため、毎回すべての前提情報を入力し直す必要がない。

  一方、会話が進むにつれて入力トークン数が増えることも確認できた。長時間の対話では、APIの利用コストやコンテキストウィンドウの上限を考慮し、古い履歴の削除や要約などを検討する必要があると考えられる。

  また、実装の過程では、PythonのソースコードをBashターミナルへ直接入力したことで構文エラーが発生した。Pythonファイルの編集とターミナルでのコマンド実行の違いを理解し、エラー発生時にはファイルを復旧してから機能追加・テストを進める重要性を学んだ。

  今後は、単に履歴を保持するだけでなく、保持する履歴の長さを制御した場合の回答品質とトークン使用量の変化についても検証したい。
