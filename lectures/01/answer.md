# 第1回 解答

## 演習

- 講座に固有の質問（宿題の3レベル）へのモデルの回答（要約でよい）：
・正確には答えられない。
・詳しくは、調べてみよう、というような答え。

- 用語集の正しい意味と比べて気づいたこと：
・答えのたとえは理解にはく奪が、「元の知識を壊さない」「家庭用GPUで学習できる」とは、必ずしもそうなるとは限らず、簡略化された説明もあると思った。正確性という点では、まだ完璧とはいえなさそう。

- 表示できたトークン数（入力 / 出力）：７→７２７

## 宿題

- 取り組んだレベル：基礎 ＋　実装　の２つ

- やったこと：基礎：モデルを切り替えて、3回ずつやってみた。
　　　　　　　実装：app/ask.pyを改修し、会話履歴を保ったまま続けて質問できるようにした。
　　　　　　
- 基礎の結果：
1.gemini-3.5-flash　：3回成功（入力７→出力７２７、７→７２８）
　・付箋のたとえを使い、仕組み・メリット・用途を幅広く説明。

2.gemini-3.5-flash-lite　：成功（３７→４２４、７→５８８、７→６２１）
　・比較的短く要点を説明。
　・ただし、「効率よく効果的に」の語句重複あり。
　
3.gemini-3.8-flash　２回成功、1回エラー（成功時３５→５７０，７→７８３）
　・1回目は混雑によるエラー
　・行列分解や低ランク行列に触れた説明もあり。
　・解答の長さにばらつき有り

- 気づき・疑問：
・同じ質問でも、モデルによって説明の長さや内容が違った。
・同じモデルでも、毎回同じ答えになるわけでもないことが分かった。
・出力トークンが多いほど、説明は詳しいが、内容が正しいとは限らない。内容の確認が必要。
・なぜ、最後のモデルで実行時にエラーが起きたのか？
・なぜ、同じように問題を出したのに、入力トークン数がちがうのか？
・この画面の下の入出力画面、あとから入力すると、変な文字が入力されて困る。どうすれば直るのか？
・この問題には、gemini-3.5-flashが一番よさそう。

実装の結果：追加したコード
parser.add_argument(
    "--chat",
    action="store_true",
    help="会話履歴を保って続けて質問する",
)
args = parser.parse_args()

if args.chat:
    chat()
    return

実装の気づき・質問：
・チャットを使うと、意外と簡単にコード修正できた。
・変更の中心は、終わりの前に、会話モードを追加して実行方法を切り替える処理を入れたところ。
