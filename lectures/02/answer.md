# 第2回 解答

## 宿題
### 1. 取り組んだレベル

**基礎**

LoRAによるファインチューニングについて、学習エポック数（`num_train_epochs`）を変更し、回答形式の遵守率、内容正解率、最終loss、学習時間への影響を比較した。

### 2. 変更した設定とその理由

変更したパラメータは、`CONFIG` 内の `num_train_epochs` である。

- 変更前：`num_train_epochs = 20`
- 変更後：`num_train_epochs = 15`
- その他の設定：変更なし（`lora_r = 16`、`lr = 2e-4` など）

今回の学習データは14件と少ないため、20エポックでは同じデータを繰り返し学習することになり、過学習が発生する可能性があると考えた。

そこで、エポック数を15に減らすことで、過学習を抑え、未知の質問に対する性能を維持または改善しながら、学習時間を短縮できるのではないかと考えた。

### 3. 実験結果

元の設定（20エポック）と変更後（15エポック）でそれぞれ学習を実行し、`result.json` に記録された結果を比較した。

評価には、両方とも同じ21問のテストデータを使用した。

| 評価項目 | 変更前（20） | 変更後（15） |
|---|---:|---:|
| 学習前 format_rate | 9.52% | 9.52% |
| 学習前 content_rate | 0.00% | 0.00% |
| 学習後 format_rate | 100.00% | 100.00% |
| 学習後 content_rate | 90.48% | 90.48% |
| 最終loss | 0.01401 | 0.02244 |
| 学習時間 | 238.63秒 | 176.04秒 |

**結果の比較と考察**

まず、`format_rate`（形式遵守率）は、どちらの設定でも学習前の9.52%から学習後の100%に改善した。これは、LoRAによるファインチューニングによって、指定されたJSON形式で回答する能力が向上したことを示している。

一方、`content_rate`（内容正解率）は、どちらも学習前の0%から学習後の90.48%に改善し、21問中19問に正解した。したがって、エポック数を20から15に減らしても内容正解率は低下しなかったが、向上も確認できなかった。

また、両方とも21問中2問が不正解であった。ただし、`result.json` には個々の質問に対する正誤が記録されていないため、不正解となった2問が両設定で同じ問題だったかどうかは判断できない。今回確認できたのは全体の正解率が同じだったという点であり、個々の質問への回答傾向まで同一だったとはいえない。

最終lossは20エポックの0.01401に対し、15エポックでは0.02244とやや高くなった。これは学習回数を減らしたことで、学習データへの適合度が相対的に低くなったためと考えられる。しかし、評価データでの正解率は同じであり、今回の結果ではlossをさらに小さくすることが、必ずしも評価スコアの向上につながるわけではないことが分かった。

学習時間については、238.63秒から176.04秒へと約62.59秒短縮され、約26.2%の削減となった。

以上の結果から、今回の条件では、15エポックでも20エポックと同等の評価性能を達成でき、学習効率を改善できることが確認できた。一方、当初予想した過学習の抑制による正解率の向上は確認できず、今回の実験結果だけでは過学習が発生していたとは断定できない。

**追加の知識質問について**

21問の評価とは別に実施した4問の知識質問についても、両設定の結果を比較した。

その結果、20エポックと15エポックでは、4問すべてで学習後の回答内容と分類が一致していた。

FAQにない「担当教員の名前は何ですか」「次回の講義のテーマは何ですか」という質問に対しては、どちらの設定でも「FAQには記載がなく、確認が必要」と回答できていた。

しかし、FAQにない「この講座の最終課題の締切はいつですか」という質問に対しては、両設定ともFAQに記載された一般的な課題の提出期限を流用し、`needs_review: false` として断定していた。

なお、対照として出題された「課題の提出期限はいつですか」はFAQに根拠がある質問であり、提出期限を断定したこと自体は誤りではない。

この結果から、エポック数を減らしても、追加の知識質問に対する回答傾向に変化は見られなかった。また、根拠のない質問に対して別の情報を当てはめて回答してしまう問題も残っていることが分かった。

ただし、これらは21問の評価とは別の質問であるため、21問中の不正解2問が両設定で同一であったことを示すものではない。

### 4. ファインチューニングが向く場面・向かない場面についての考察

**ファインチューニングが向いている場面**

今回の実験では、学習前の形式遵守率が9.52%だったのに対し、学習後には100%となった。このことから、ファインチューニングは、特定のJSON形式で回答させるなど、出力形式や回答パターンを統一したい場合に有効だと考えられる。

例えば、FAQへの回答を決まった形式で出力するシステムや、文章から必要な情報を抽出して構造化するシステムなど、一定のルールに沿った応答が必要な場面に向いている。

**ファインチューニングが向いていない場面**

一方、ファインチューニングを行っても、回答内容が必ず正しくなるとは限らない。

今回の実験では、形式遵守率が100%になった一方で、内容正解率は90.48%にとどまった。また、追加の知識質問では、FAQにない「この講座の最終課題の締切」について、確認を求めずに、FAQに記載された別の期限を根拠として回答を断定する例が、どちらの設定でも見られた。

このことから、正しいJSON形式を出力できることと、根拠に基づいて正確に回答できることは別の能力であると分かった。

また、今回の追加質問では、根拠のない質問に適切に確認を求められた例もあったため、ファインチューニングによって知識に関する回答が一律に改善しないわけではなく、質問の内容によって適切な回答と不適切な回答が混在することも確認できた。

そのため、最新情報や頻繁に変更される情報への回答、正確な根拠が必要な質問への対応では、ファインチューニングだけに頼ることは適切ではないと考える。

このような場面では、外部の文書やデータベースから情報を検索して回答に利用するRAGなどの仕組みと組み合わせる方が適している。

**まとめ**

今回の実験から、LoRAによるファインチューニングは、少量の学習データでも回答形式の遵守率を大きく改善できることが分かった。また、学習エポック数を20から15に減らしても同等の評価性能を維持でき、学習時間を約26.2%短縮できた。

一方で、両設定とも21問中2問が不正解であったが、その2問が同じ問題だったかどうかは確認できなかった。また、追加の知識質問では両設定の回答がすべて一致し、根拠のない質問に対して断定する問題も残っていた。

以上から、ファインチューニングは回答形式や応答パターンの調整に有効である一方、内容の正確性まで保証するものではないため、事実の正確性が重要な場面では外部情報の検索などと組み合わせることが重要だと考えた。
