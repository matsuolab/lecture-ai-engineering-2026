## 宿題

### 取り組んだレベル
発展

### データと実験方法
講座の `data/glossary.json` と `scripts/make_sft_dataset.py` を使い、58用語から116件のQ&A学習データを作成した。学習データは、ユーザーの質問と用語集の定義を回答とする `messages` 形式である。

`Qwen/Qwen3.5-0.8B` に対し、量子化なしのLoRA学習を実行した。主な設定は、LoRAのrankが16、alphaが32、学習率が0.0002、学習が3エポックである。116件を使用するため、元の演習の20エポックから3エポックに変更した。

評価には、用語を直接聞く質問、用語名を含まない言い換えの質問、用語集にない語の質問を各3問、計9問用意した。学習用の質問文との完全一致がないことを確認し、学習前後で同じ質問・同じ生成条件を使用した。生成上限は256トークンとし、定義を入力に与えずに回答させた。

### 学習結果

| 項目 | 結果 |
|---|---:|
| 学習データ数 | 116件 |
| エポック数 | 3 |
| ステップ数 | 45 |
| 学習時間 | 76.48秒 |
| 学習対象パラメータの割合 | 約0.8421% |
| 5ステップ時点のloss | 3.746626 |
| 45ステップ時点のloss | 1.198043 |
| 生成上限に到達した回答数 | 学習前8/9件、学習後0/9件 |

lossは低下し、学習後の回答は短い定義のような文章になった。ただし、短くなったことが、そのまま内容の正確さを意味するわけではなかった。

コンテキストウィンドウの直接質問では、学習前は文脈を理解して関連情報を提供する仕組みとして説明していたが、学習後は「入力と出力の合計トークン数の上限」と答え、定義の中心に近づいた。一方、言い換えた質問では「総字数」「文字数の上限」と答えており、トークン数という重要な点を正確に説明できなかった。

トークンの直接質問でも、学習後は「LLMがテキストを扱う最小単位」と答えたが、「ハイパーフラグ」など不適切な説明を付け加えた。このため、定義の一部を答えられても、回答全体の正確さは保証されないと分かった。

用語集にない3語についても、学習後のモデルは確認を求めず説明を生成した。確率微分方程式への回答では「本講座では確率微分（PDE）の形式をモデルとして使う」と述べ、学習に使った用語集に根拠のない講座固有の説明を加えた。今回の学習データには未知の語への回答を控える例がないため、その判断を学習できたとはいえない。

### 用語集の検索との比較
教材の `search_glossary` を使い、質問文をそのまま検索する場合と、人が対象の用語名を指定する場合を比較した。

| 評価対象 | 質問文をそのまま検索 | 人が用語名を指定して検索 |
|---|---|---|
| 直接質問3問 | 目的の項目を3/3問で取得 | 目的の項目を3/3問で取得 |
| 言い換え3問 | 目的の項目を0/3問で取得 | 目的の項目を3/3問で取得 |
| 用語集にない語3問 | 3/3問で該当なし | 3/3問で該当なし |

言い換えたトークンの質問では、「LLM」の項目が返ったが、目的の「トークン」の項目は返らなかった。他の言い換え2問は該当なしだった。検索結果があることと、目的の定義を取得できることは別である。

用語名を指定すると目的の定義を原文で取得できた。ただし、用語名の指定は人が行ったため、検索が自動で言い換えを理解できた結果ではない。また、今回は検索結果の取得を比較しており、検索結果をLLMに渡して回答を生成する仕組み全体は評価していない。

### 考察
今回の学習では、回答を短い定義のような文体に近づける効果と、一部の用語の説明が改善する様子を確認した。このことから、一定の回答形式や文体にそろえる用途は、ファインチューニングの候補になると考える。

一方、学習済み用語でも言い換えへの対応は不安定で、誤った説明や根拠のない断定が残った。正確な定義の参照や、資料に記載がないことの判定を、この学習だけに任せるのは難しい。

検索は、適切な用語を指定できれば定義を原文で確認できる。用語集を更新して検索すれば、モデルの再学習をせずに変更を参照できる点も利点である。一方、今回の文字列検索は言い換えに弱く、質問から検索語を選ぶ工夫が必要だった。

今回の結果から、回答の振る舞いを整えるための学習と、正確で更新可能な根拠を取得するための検索を組み合わせる方法を検討したい。ただし、組み合わせた場合の効果は今回検証していない。

評価は9問のみで、用語集にある語は学習にも含めている。また、学習前の回答は8問が生成上限に達している。したがって、この結果から未学習の用語への一般化や、モデル全体の性能向上を結論づけることはできない。

学習・学習前後の回答生成・検索比較は、自分のColab環境で実行した。AIをコード作成と結果整理の補助に使用した。
