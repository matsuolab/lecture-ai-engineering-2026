### ファインチューニングが向く場面・向かない場面（考察）

- **向く場面**：出力の形式や言い回しを固定したいとき。今回は 14 件・約 1 分の学習でも JSON 形式の遵守率が 0.10 → 1.00 になった。プロンプトで形式を指示しても守れない小さいモデルを、決まった API 形式・定型の応答・社内の文体に合わせる用途には効果が大きく、コストも小さい。
- **向かない場面**：
  - 新しい知識や「根拠の有無の判断」を持たせたいとき。学習を増やすと FAQ の文を覚えるほど、FAQ に無い質問にも覚えた文で断定しやすくなった（根拠なしでの断定 1/6 → 3/6）。事実の正しさが重要な用途は、検索（RAG）で根拠を渡し、根拠が見つからないときの扱いをプログラム側で判定する方が安全。
  - 内容が頻繁に変わるとき。FAQ の日付が変われば再学習が必要になる。検索なら文書を差し替えるだけで済む。
- **学習量の決め方**：形式だけが目的なら少ないエポックで足り、エポックを増やすと文面は安定する一方で過学習による断定が増えうる。loss だけでなく、根拠なしの質問を含む評価セットで format_rate・content_rate・needs_review を分けて見て決めるべき。今回の条件なら、5 と 20 の間（例：10 前後）を同じ評価で比べるのが次の一手。
