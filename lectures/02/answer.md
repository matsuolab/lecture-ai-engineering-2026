## 宿題

- 取り組んだレベル：発展
- 変えた設定やデータ：`uv run python scripts/make_sft_dataset.py > glossary_sft.jsonl` を実行。用語集58語から、各語について2種類の質問を作り、合計116件の `messages` 形式 JSONL を生成した。各レコードは user の質問と assistant の定義からなる。評価用の質問は学習例と異なる言い回しで用意した。
- 評価質問と正解：用語集にある語「LoRAとは何ですか？」は、事前学習済みの重みは固定し低ランク行列で表す更新分だけを学習する PEFT 手法と説明する。言い換え「基盤モデルを固定したまま、追加した小さなパラメータだけを学習する方法は何ですか？」は LoRA と答える。未掲載語「蒸留とは何ですか？」は推測せず、用語集に見つからないと答える。

- 結果（比較表や数字）：生成データは116件で、全件が `messages` キーを持つ2メッセージ（user/assistant）形式であることを確認した。既存の `search_glossary` では「LoRAとは何ですか？」は LoRA の定義が見つかり、「蒸留とは何ですか？」は見つからなかった。一方、言い換え質問は「事前学習済みモデル」という部分一致から「事前学習」が返り、LoRA の正しい検索結果にならなかった。学習前後のモデル出力と正解率は未計測。ノートブックの学習実行環境は Colab の T4 GPU を前提としており、この Codespace には `torch` がなく実行できなかった。Colab では `glossary_sft.jsonl` をアップロードし、`Dataset.from_list(...)` で学習データとして読み込んだうえで、同じ評価質問を学習前後に実行して比較する必要がある。
- ファインチューニングが向く場面・向かない場面についての考察：学習は、用語に対する説明の仕方や回答形式を一定にし、用語名を含まない質問にも意味から答えられるようにする用途が期待できる。一方、今回の116件だけで、未知語には答えないという判断や正確さまで身につくとは限らず、学習データに誤りがあればそれも覚える。用語の追加・修正のたびに再学習が必要で、根拠となる定義を明示しにくい。検索は学習不要で用語集の更新をすぐ反映でき、根拠を提示しやすく、未掲載語も「見つからない」と判定できる反面、言い換えに弱く、部分一致では誤った用語を返すことがある。事実の更新や出典の提示には検索、回答の文体・形式の統一にはファインチューニングが適し、必要なら検索結果をモデルに渡す構成がよいと考える。
