# AIエージェントにおけるシステムプロンプトの比較分析

AIエージェントのプロンプトは、大きく分けて「ツールを操作するための基盤的なルール」と「特定のタスクを遂行するためのドメイン固有の指示」の2層構造になっています。

## 1. 比較一覧

| 項目 | `app/agent.py` の `INSTRUCTIONS` | システムプロンプト生成コード (基盤側) |
| :--- | :--- | :--- |
| **役割** | **「教育者」としての個性・ルール** | **「ツール操作者」としての規律・作法** |
| **主な対象** | 学習者（ユーザー）への回答方針 | AIのシステム全体とツールの管理 |
| **具体的な指示** | 用語集を見ろ、宿題の答えを教えるな等 | bashを使え、簡潔に答える、パスを表示しろ等 |
| **ドメイン** | AIエンジニアリング講座（特化型） | 汎用的なコーディング・操作（汎用型） |

---

## 2. 詳細分析

### `app/agent.py` が担う役割（学習支援特化）
このファイル内の `INSTRUCTIONS` は、AIが「何のために、どう答えるべきか」を定義しています。
*   **ツール利用の優先順位:** 「用語回答時は `search_glossary` を先に使え」といった、業務フローの指定。
*   **誠実性と制限:** 「知らないことは推測しない」「宿題の答えを直接教えない」といった、教育者としての境界線の設定。
*   **出力フォーマット:** 「最後に第N回と記載せよ」という、ユーザー体験（UX）のための定型指示。

### システムプロンプト生成コードが担う役割（基盤・環境制御）
このコードは、AIがツールを正しく安全に使いこなすための「OS（オペレーティングシステム）」のような役割を担います。
*   **ハネネス（基盤）としての基本作法:** 「簡潔に答える」「ファイルパスを明確にする」といった、AIの品質を維持するための共通ルール。
*   **環境コンテキストの注入:** 現在の作業ディレクトリ（`cwd`）や、利用可能なツールの定義、MCPサーバーの接続設定など、実行環境に応じて動的に生成される情報の付与。
*   **自己参照ドキュメント:** 「pi」というツールの使い方（マニュアルやドキュメント）へのアクセス経路を定義し、ユーザーが使い方に迷わないように誘導する。

---

## 3. 結論：2つのプロンプトの関係性

これらは**「階層」が異なるプロンプト**として機能しています。

1.  **システムプロンプト生成コード:** 「AIというシステムが、環境を認識し、ツールを安全に扱うための **How（やり方）**」
2.  **`INSTRUCTIONS`:** 「そのAIが、学習者に対してどのような知識を提供し、どう振る舞うかの **What（何をすべきか）**」

これらが組み合わさることで、AIは「AIE2026の講座を専門的に教えつつ、コマンド実行などのツールも適切に使いこなす」という高度な振る舞いを実現しています。
