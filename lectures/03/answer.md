## 演習

- 第1回（素のLLM）とエージェントの回答の違い：
  同じ質問「AIE2026の講座の宿題にある「3レベル」とは何ですか？」で比べた。第1回の素の gemini-3.5-flash-lite は、
  講座のことは参照できないと断ったうえで、一般論として「レベル1(基礎)・レベル2(標準)・レベル3(発展)」と答えた。
  エージェントは `search_glossary` で用語集を調べてから答えたので、次の点まで用語集どおりに答えられた。
  - 「基礎（講義内容の確認）・実装（自分でコードを書く）・発展（調査や試行）」の3段階であること
  - 「どれか1つに取り組めば完了」「原則として採点しない」という講座固有のルール
  - 回答の最後に「第1回」と関係する回を示したこと（`INSTRUCTIONS` の指示どおり）
- `--trace` で見えたツール呼び出し（ツール名と引数）：
  - 「3レベル」の質問：`search_glossary({'query': '3レベル'})`
  - 「LoRAとQLoRAの違いは？」：`search_glossary({'query': 'LoRA'})` と `search_glossary({'query': 'QLoRA'})`。docstring の「query には調べたい用語を1つだけ入れる」のとおり、2つの用語を別々に検索した
  - 「第2回の内容から確認問題を1問出して」：`get_lecture_summary({'lecture': 2})`
- 1つの質問での LLM 呼び出し回数（`requests`）：
  3つの質問とも `requests=2` だった。

  | 質問 | requests | tool_calls | 入力 / 出力トークン |
  |---|---|---|---|
  | 3レベル | 2 | 1 | 985 / 134 |
  | LoRAとQLoRAの違い | 2 | 2 | 1398 / 195 |
  | 第2回の確認問題 | 2 | 1 | 1382 / 312 |

  LoRA と QLoRA の質問はツールを2回呼んだのに、`requests` は 2 のままだった。1回目の LLM 呼び出しで2つの検索をまとめて頼み、2回目で回答を作ったと考えられる。
- 追加したツールと、docstring に書いた説明：
  演習では `make_quiz` を作れなかった。確認問題を頼むと、モデルは代わりに `get_lecture_summary(2)` で第2回の要点を読み、自分で3択問題を作った。ヒントは出すが答えは書かなかった（`INSTRUCTIONS` の「答えそのものは書かず」のとおり）。ただし、`make_quiz` のように用語集の定義を答えとして使うわけではないので、問題の正しさはモデル任せになる。宿題では、承認付きのツール `save_learning_log` を追加した。

## 宿題

- 取り組んだレベル：実装（使ったモデル：gemini-3.5-flash-lite）
- やったこと：
  - `app/tools.py` に `save_learning_log(content: str)` を追加した。
    - 保存先は `learning_log/`
    - ファイル名は本文から作らず、時刻（`YYYYMMDD-HHMMSS.md`）から作る。同じ時刻なら `-1`・`-2` と連番にし、`open(..., "x")` で上書きを防ぐ。100 個重なったら、例外ではなく「保存しませんでした」と返す
    - 本文は前後の空白を除き、空なら保存しない。最大 5,000 文字で、超えた分は切って、戻り値に「省略しました」と書く
    - docstring：「利用者が「学習記録を保存して」「今日の学びを残して」と頼んだときに使う。content に保存する本文を入れる。保存は取り消しにくいので実行前に承認が必要。」
  - `app/agent.py`
    - `output_type=[str, DeferredToolRequests]` にし、`requires_approval=True` で登録した。`INSTRUCTIONS` に「利用者が学習記録の保存を頼んだら、save_learning_log を使う」を足した
    - `ask_approval` で `[y/N]` を聞く。NFKC 正規化するので、全角の「ｙ」も承認になる。それ以外の入力と、Ctrl-D・Ctrl-C は拒否にする
    - `run_with_approval` で、承認の結果と会話履歴を渡して再実行する。質問は重ねて送らず、`RunUsage` を引き継いで利用量を合計する
  - `tests/test_learning_log.py` を追加した。保存先を `tmp_path` に差し替える fixture を置き、次のことをテストした
    - 空白の除去・空の本文
    - 連番・上書きしないこと・保存先のパスが変わらないこと
    - 切り詰め・101 回目の衝突
    - 承認と拒否の各入力・入力の中断・質問の重複がないこと
- 結果：
  - `uv run pytest -q`：26 passed
  - 実機で確認した。`learning_log/` を空にしてから、`uv run python -m app.agent --trace "LoRAについて調べて、今日の学びとして学習記録に保存して"` を 2 回実行した

    | | 承認（y） | 拒否（n） |
    |---|---|---|
    | ツール呼び出し | `search_glossary({'query': 'LoRA'})` → `save_learning_log({'content': 'LoRAについて学習しました。…'})` | 同じ順で呼んだ（本文は別の文） |
    | `[tool return]` | 学習記録を保存しました: 20261107-020823.md | 利用者が拒否しました。 |
    | `learning_log/` の件数 | 0 → 1 | 1 → 1（増えない） |
    | `requests` / `tool_calls` | 3 / 2 | 3 / 1 |
    | モデルの回答 | 「学習記録に保存いたしました」 | 「承認が得られなかったため、保存を中止しました」 |

  - 保存されたファイルの中身は、`[approval]` に出た `content` と一字一句同じだった
- 気づき・疑問：
  - **`requests` が演習の 2 から 3 に増えた**：① `search_glossary` を呼ぶ → ② `save_learning_log` を呼んで承認待ちで止まる → ③ 承認の結果を受けて最終回答を作る、の 3 回。`run_sync` は 2 回に分かれるが、`RunUsage` を引き継いだので合計で表示された。
  - **拒否すると `tool_calls` が 1 減った**：実行されなかった呼び出しは数えられない。
  - **保存する本文に、用語集にない言葉が入った**：「メモリを大幅に削減」は、用語集の LoRA の定義にない言葉だった。本文にはモデルの補足が混ざり、そのまま記録に残るので、承認するときに本文を読む意味がある。
  - **本文は毎回違う**：同じ質問でも、2 回の本文は別の文だった。形式をそろえたいなら、docstring で指定する必要がある。
  - **実機の証拠には `--trace` が必要**：途中で、中身が同じファイルが 9 個できていた。モデルが保存したものか確かめられなかったので、別の場所に移し、件数 0 から確認した。
  - **疑問**：本文が長いと、`[approval]` の 1 行では読みにくい。承認する前に本文を書き換えられるようにする（`DeferredToolResults` で引数を差し替える）とよいと考えられる。
