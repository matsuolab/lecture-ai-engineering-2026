## 宿題
　##基礎
- **やったこと**：
  `app/tools.py` の `search_glossary` 内にある docstring（指示文章）を変更し、`--trace` 付きで「LoRA とQLoRAの違いは？」を実行してモデルの挙動とログ（呼び出し回数・トークン数）の変化を比較・検証した。

- **結果**：
  - **パターン1（「1つだけ指定」の制約文を削った場合）**:
    - ログ: `search_glossary({'query': 'LoRA'})` と `search_glossary({'query': 'QLoRA'})` の計2回呼び出し（`tool_calls=2`, トークン数 1214）。
    - 挙動: 制約文を削っても、モデルが自律的に質問文から2つの用語を分解し、2回ツールを呼び出して情報を正確に取得した。
  - **パターン2（docstring を「リンゴはおいしいです」等に変更した場合）**:
    - ログ: `search_glossary({'query': 'LoRA'})` のみ 1 回呼び出し（`tool_calls=1`, トークン数 969）。
    - 挙動: 回答自体は正しく生成されたものの、ツールの呼び出し回数が2回から1回へと減少した。

- **気づき・疑問・根拠（考察）**:
  - **なぜパターン2で「1回しか呼ばれていない」のに正しい回答が作れたのか？（根拠）**
    - 1回目の `search_glossary({'query': 'LoRA'})` の実行時、用語「QLoRA」の中に「LoRA」という文字列が含まれていたため、1回目の検索戻り値（`[tool return]`）の中に **LoRA と QLoRA の両方の定義データ** が偶然まとめて含まれて返されていたことが `--trace` ログから確認できた。そのためモデルは1回目で必要な情報をすべて入手し、回答を生成できた。
  - **なぜ指示（docstring）の書き換えによって呼び出し回数が変わったのか？（根拠）**
    - パターン1（丁寧な指示）では「1回目の検索結果にQLoRAが含まれていた」としても、指示の丁寧さからモデルが「念のため QLoRA でも個別に検索して確実に情報を揃えよう」と几帳面に2回目を呼び出す計画を立てていた。
    - 一方、パターン2（不適切な指示）ではガイドラインが失われたことでモデルの計画性が曖昧になり、「1回目で両方のデータが取れたからもうこれでいいや」と大雑ばな判断をし、2回目の呼び出しをスキップ（ドロップ）する挙動の変化が起きた。
  - **結論**:
    - `docstring` は単なるメモではなく、モデルに送られるプロンプト（指示書）としてトークン消費量やモデルの「行動計画（何回・どうツールを呼ぶか）」に直接影響を与える重要な制御用ラベルであることを実証できた。

  - `--trace` 付きで「今日の学習内容（LoRAとQLoRAの違い）を learning_log に記録して」を実行した。

- **気づき・疑問**：
  - 承認付きツール（`requires_approval=True`）を扱う場合、ツール側の関数定義だけでなく、呼び出し元（エージェント側）で承認待ちの戻り値を受け取る型定義（`output_type=[str, DeferredToolRequests]`）やハンドリング処理が必須になることを学んだ。
  - ユーザーが具体的な文章を指定しなくても、AIがツールを組み合わせて情報検索・要約を行い、保存用の引数を自律的に生成して人間の確認を求める安全な制御フロー（Human-in-the-Loop）の仕組みを理解できた。
