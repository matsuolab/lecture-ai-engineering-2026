## 宿題

- 取り組んだレベル：基礎 
- やったこと：docstring に入力フォーマット例を追記、「使用しない条件」を明記、INSTRUCTIONS に「実行前の理由付け」を義務付け、ツール呼び出し回数の上限を設定、回答フォーマット（表や箇条書き）を指定
- 結果：docstring に入力フォーマット例を追記

引数の型エラーや再試行がなくなり、1発で呼べてステップ数が減る。

docstring に「使用しない条件」を明記

既知の事柄に対する無駄なツール呼び出し（過剰な検索など）がゼロになる。

INSTRUCTIONS に「実行前の理由付け」を義務付け

思考ログ（Thought）が出力され、無関係なツールの誤選択が減る。

INSTRUCTIONS にツール呼び出し回数の上限を設定

終わりのない再検索ループが止まり、取得済みデータだけで回答をまとめる。

INSTRUCTIONS に回答フォーマット（表や箇条書き）を指定

ツール呼び出し手順自体は変わらず、最終出力の見た目・構造だけが揃う。

- 気づき・疑問：
ツールの docstring は引数仕様や使用条件を明示することで、型エラーや見当違いな呼び出しを直接防ぐ役割を果たします。
一方、INSTRUCTIONS はエージェント全体の思考プロセスや呼び出し制限、最終回答の形式といった行動方針を制御します。
指示や説明が曖昧だと無駄な試行錯誤やリトライが増加し、レイテンシや API コストの増大につながります。
したがって、プロンプトの解像度を上げるだけで、ツール選択の精度向上とステップ数の削減を同時に達成できます。
結果として、ツールの個別仕様（docstring）と全体の行動規範（INSTRUCTIONS）を明確に役割分担させて記述することが、堅牢なエージェント設計において不可欠であると気づきました。
