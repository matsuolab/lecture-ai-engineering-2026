### 2回目
- 取り組んだレベル：実装
- やったこと：
    - `app/tools.py` に `save_learning_log` を追加し、学びを `learning_log/` に Markdown で保存するようにした
    - ファイル名の日付はモデルに任せず、日本時間の今日をコード側で付けるようにした
    - `app/agent.py` で import を追加し、`requires_approval=True` を付けてツールを登録した
    - `output_type` に `DeferredToolRequests` を追加した（承認待ちを戻り値として扱えるようにするため）
    - INSTRUCTIONS に、「学んだ」「わかった」などのときに返事の前に `save_learning_log` を使う指示を足した
    - CLIで保存前に y/N を聞く処理を `app/agent.py` の `main()` に書いた。
      `run_sync` のあとに、戻り値が `DeferredToolRequests`（承認待ち）ならループする。
      待ちの呼び出しごとにツール名と引数を表示し、`input("実行してよいですか？ [y/N]: ")` で聞く。
      `y` ならその呼び出しを承認（`True`）、それ以外なら `ToolDenied` で拒否する。
      その結果（`DeferredToolResults`）と、それまでの会話（`message_history=result.all_messages()`）を渡してもう一度 `run_sync` し、保存するかしないかを確定してから回答を出す。
- 気づき・疑問：
    - doctoringをしっかり書かないと、明示的に記録してと言わない限り記録してくれない。
    - output_typeであらかじめ定義しておかないと、エラーとして扱われてしまう
    - 僕たちのコードがまずいくところが、SDKで今回でいうpydantic AIであり、この構文どうりに書くことでそのSDKがモデルのAIの形式に変換してくれる。それによって処理が行えるというメタ的な理解はできるようになった。

  - `adk run` で動かした
- 書き方の違い：下の表参照。指示・ツールは共通で、SDK の文法と「誰が起動ボタンを持つか」が違う
- 気づき・疑問：
    - 気づき：ADKならば比較的シンプルでわかりやすいコードで動くものを作れるのだなと感じました。
    - 比較（書き方と、同じような質問を投げたときの回答・ふるまい）

| 比較項目 | Pydantic AI | ADK |
|---|---|---|
| 指示の渡し方 | `instructions=INSTRUCTIONS` | `instruction=INSTRUCTIONS`（中身は `app.agent` から import） |
| ツールの渡し方 | 作ったあとに `agent.tool_plain(...)` を繰り返す | 作るときに `tools=[...]` でまとめて渡す |
| 入口の名前 | 変数名は自由（この講座では `agent`） | `adk run` が見つけるために `root_agent` が必要 |
| ファイルの役割 | 定義に加えて CLI・trace・承認など動かすコードも同じファイルに書く | 定義が中心。対話ループは `adk run` に任せる |
| 動かし方 | `uv run python -m app.agent "質問"`（自分の `main()` が起動ボタン） | `adk run adk_agent/glossary_agent`（ADK 付属のコマンドが起動ボタン） |
| 答えの長さ | 比較的短め〜中くらいで、要点をまとめることが多い | 見出しや箇条書きで、少し長めに整理して返すことが多い |
| 用語集の使い方 | 講座固有の語は用語集っぽい定義で答える（推測だけの一般論になりにくい） | 同様に用語集の内容に沿って答える（「3レベル」なども宿題の定義に近い） |
| 関係する回の明示 | 回答の末尾などに「第N回」を付けやすい | こちらも「第1回」「第2回」など関係する回を示す |
| トーン | 学習支援らしく、丁寧だが簡潔 | 丁寧で説明がやや厚い。宿題の答えそのものより説明寄り |
| 対話の続きやすさ | 1回のコマンドで質問→回答が基本（続きはまたコマンド） | `adk run` の対話の中で、続けて質問しやすい |
