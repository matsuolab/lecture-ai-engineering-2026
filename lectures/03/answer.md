## 演習

- 第1回（素のLLM）とエージェントの回答の違い：
質問「AIE2026の講座の宿題にある「3レベル」とは何ですか？」を、どちらも gemini-3.5-flash-lite で比べた。
  - 第1回 app.ask：講座を知らないため、「初級・中級・上級」のような一般的な段階分けとして説明した。「基礎・実装・発展」「どれか1つで完了」「採点しない」には触れず、用語集の定義と一致しなかった。「講座によって異なる」と前置きしつつ具体例をもっともらしく並べ、出力は 575 トークンと長かった。
  - 第3回 app.agent：search_glossary で用語集を検索してから答えた。「基礎・実装・発展の3段階、どれか1つで完了、原則として採点しない」と、data/glossary.json の定義と一致した。回答の最後に関係する回（第1回）が付き、出力は 142 トークンと短かった。
  - 気づき：素の LLM は「知らない」と言わず、一般論で埋めて答えた。読み手が講座を知らなければ誤りに気づけない。

- `--trace` で見えたツール呼び出し（ツール名と引数）：
  - 「3レベル」の質問：`search_glossary({'query': '3レベル'})`。query は「3レベル」だったが、用語集の aliases に "3レベル" が登録されていたため「宿題の3レベル」がヒットした。
  - 「第2回の内容から確認問題を1問出して」（make_quiz 登録後）：`make_quiz({'lecture': 2})`。返り値は `{"question": "「エポック」とは何ですか？", "answer": "学習データ全体を1周学習することを1エポックと数える。…"}`。
  - 同じ質問（make_quiz 登録前）：`get_lecture_summary({'lecture': 2})` だけが呼ばれ、モデルが講義の要点から問題を自作していた。回答の見た目はもっともらしかったが、trace を見るまで make_quiz が使われていないことに気づけなかった。


- 1つの質問での LLM 呼び出し回数（`requests`）：
  - 「3レベル」の質問：requests=2, tool_calls=1
  - 確認問題の質問（登録前・登録後とも）：requests=2, tool_calls=1
  - どれも「ツールを選ぶ1回目」と「ツールの結果を受けて回答する2回目」の2回だった。

- 追加したツールと、docstring に書いた説明：
  - ツール：`make_quiz(lecture: int) -> str`（app/tools.py に作成、app/agent.py で `agent.tool_plain(tools.make_quiz)` として登録）
  - docstring：「指定した回の用語から1つを選び、確認問題と答えを返す。「第2回の確認問題を出して」のように、復習用の問題を求められたときに使う。」
  - 処理：load_glossary() から lecture が一致する用語を集め、random.choice で1つ選び、問題と答えを JSON 文字列で返す。用語がない回は「第N回の用語が見つかりませんでした」を返す。
  - つまずいた点：最初は関数を作っただけで agent.py に登録しておらず、--list-tools が2個のままだった。また、用語がないときのメッセージ末尾の「。」がテストの期待値と違い、pytest が1件失敗した。修正後は 13 passed。



## 宿題

- 取り組んだレベル：基礎

- やったこと：
  app/agent.py の INSTRUCTIONS と app/tools.py の search_glossary の docstring を、1回に1か所だけ書き換え、同じ質問を --trace 付きで実行して基準と比べた。比べ終わるごとに git checkout で元に戻した。
  - 変更1：INSTRUCTIONS から「用語や講座に固有のことを答える前に、必ず search_glossary で用語集を確認する。」の行を削除
  - 変更2：docstring の「query には調べたい用語を1つだけ入れる（例: "LoRA"）。」を「query には調べたい用語をまとめて入れてよい（例: "LoRA QLoRA"）。」に変更
  - 質問：「LoRA とQLoRAの違いは？」（変更1では「AIE2026の講座の宿題にある「3レベル」とは何ですか？」も）

  | 基準 | LoRA とQLoRA | search_glossary('LoRA'), search_glossary('QLoRA') | 2 / 2 | 1352 |

  - 変更1：「必ず検索」の行を消しても、両方の質問で検索は行われ、回答の内容もほぼ同じだった。入力トークンはどちらも 48 減っており、削除した行がモデルに届かなくなったことは確認できた。

- 気づき・疑問：
  - 指示は INSTRUCTIONS と docstring の2か所にある。docstring にも「答える前に使うこと」と書いてあるため、INSTRUCTIONS の1行を消しても検索が止まらなかったと考えられる。片方を消してももう片方が同じ役割を果たしており、ふるまいを変えるには両方を見る必要がある。

  - 変更2で入力トークンが大きく減ったのは、基準では 'LoRA' の検索が「QLoRA」にも部分一致し、同じ項目が重複して返っていたためではないかと考えている（未検証）。
