# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：
  エージェントは用語集や講義要約をツールで検索し、その結果を利用して回答できる。素のLLMとの直接比較は今回実施していない。

- `--trace` で見えたツール呼び出し（ツール名と引数）：
  - `search_glossary({'query': 'LoRA'})`
  - `get_lecture_summary({'lecture': 2})`
  - `make_quiz({'lecture': 2})`
  質問の内容によって、1つまたは複数のツールが呼び出された。

- 1つの質問での LLM 呼び出し回数（`requests`）：
  - 用語検索：2 requests、1 tool call
  - 講義内容とLoRAの仕組みを合わせた質問：3 requests、2 tool calls
  - 確認問題の作成：2 requests、1 tool call

- 追加したツールと、docstring に書いた説明：
  `make_quiz(lecture: int) -> str` を追加した。指定した回の用語集から用語を1つランダムに選び、問題と答えをJSON形式で返す。docstringには、講義内容の理解度を確認したいときに使うことを記述した。

## 宿題

- 取り組んだレベル：基礎

- やったこと：
  1. `app/agent.py` の INSTRUCTIONS から、用語集を必ず検索する指示を一時的に削除し、同じ質問を実行してツールの呼び出し方を比較した。
  2. `app/tools.py` の `search_glossary` の docstring を変更し、検索語を複数指定できるように説明を変更した。
  3. 用語集に存在しない「量子もつれ」について質問し、INSTRUCTIONS の有無による回答の違いを確認した。

- 結果：
  1. 用語集を必ず検索する指示を削除しても、モデルは `search_glossary` を呼び出した。
  2. 複数の用語を指定する説明に変更すると、`LoRA, QLoRA` という引数で検索ツールが呼び出された。
  3. 用語集にない用語について、指示を削除した場合は、モデルがより断定的に説明し、根拠のない関連講義番号も回答した。元の指示に戻すと、用語集にないことを伝えるようになった。

- 気づき・疑問：
  INSTRUCTIONS はエージェント全体の動作に影響し、docstring はモデルがツールをいつ、どのように使うかの判断に影響することが分かった。また、ツールを使っても、モデルの回答が常にツールの結果だけに基づくとは限らないため、指示とツールの設計が重要だと感じた。
