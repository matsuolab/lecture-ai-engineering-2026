## 宿題

- 取り組んだレベル：基礎
- やったこと：
	- `app/agent.py` のINSTRUCTIONSから「用語や講座に固有のことを答える前に、必ず search_glossary で用語集を確認する」という指示を一時的に外し、前後で同じ質問「LoRAとは何ですか？」を実行した。
	- INSTRUCTIONSを元に戻してから、`app/tools.py` の `search_glossary` のdocstringを一時的に変更し、同じ質問「LoRAとQLoRAの違いは？」を実行した。関数のコードや引数型は変更していない。
	- READMEの実行方法に従い、`uv run python -m app.agent --trace "質問"` を使用した。既定モデルで503が出たため、その後の全実行は同じ `gemini-3.1-flash-lite` に固定した。
- 結果：
	- 実験A（INSTRUCTIONS変更）：変更前は `[tool call] search_glossary({'query': 'LoRA'})` が1回で、`requests=2`、`tool_calls=1` だった。必須検索の指示を外した後も、同じ引数の検索が1回呼ばれ、`requests=2`、`tool_calls=1` だった。
	- 実験Aの回答は、前後ともLoRAを説明し、第2回に関連すると答えた。変更後は説明の項目立てや言い回しが変わったが、内容はほぼ同じだった。つまり、この実行では指示を外しても検索は省略されなかった。
	- 実験B（docstring変更）：変更前は `search_glossary({'query': 'LoRA'})` と `search_glossary({'query': 'QLoRA'})` がそれぞれ1回で、合計 `tool_calls=2`、`requests=2` だった。
	- docstring変更後は `[tool call] search_glossary({'query': 'LoRAとQLoRA'})` の1回になり、`tool_calls=1`、`requests=2` だった。トレース表示の戻り値は先頭120文字だけだが、関数を直接実行して確認すると、返り値にはLoRAとQLoRAの両方の定義が含まれていた。
	- 実験Bの最終回答は前後とも両用語の違いを説明し、関連回を第2回としていた。文章の表現や説明の順番は異なったが、主な説明内容に大きな差はなかった。
- 気づき・疑問：
	- INSTRUCTIONSはエージェント全体への指示だが、削除してもモデルが質問内容から必要性を判断し、ツールを使う場合がある。1回の結果だけでは、指示が影響しないとは言えず、質問や実行回数を増やして確かめる必要がある。
	- docstringはモデルがツールの使い方を決めるときの説明になる。今回は複数語を1つの文字列にまとめるよう案内したことで、検索回数と引数が変わった。一方、引数の型自体は `str` のままであり、複数引数を受け取る仕様に変えたわけではない。
	- 同じ質問でもモデルの回答文は少しずつ変わるため、ツール呼び出しの回数・引数のようなトレース上の情報と、回答内容の意味を分けて比較するのが大切だと分かった。今後は同じ質問を複数回実行し、指示や説明の変更で呼び出し方がどの程度安定して変わるかも調べたい。
