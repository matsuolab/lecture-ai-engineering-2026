# 第3回 解答

この講座では、「講座の言葉を質問すると答えてくれるAI」を作ってきた。
このAIは、辞書を引くみたいな小さなプログラム（ツール＝道具）を自分で使いながら答える。こういうAIをエージェントと呼ぶ。
言葉の説明は、その都度つける。

## 演習

### 第1回（素のLLM）とエージェントの回答の違い：

LLMというのは、文章を作るAI本体のこと。
第1回は道具なしのAI、第3回は道具ありのAI（エージェント）に、同じ質問をした。

質問：「AIE2026の講座で使う『lecNN-start タグ』とは何ですか？」
タグというのは、コードのある時点につける名前札のこと。

- 第1回のAI（app.ask）：NNを「ニューラルネットワーク」の略だと勘違いした。ニューラルネットワークというのは、人間の脳をまねた計算の仕組みのこと。そのまま「コードの始まる場所を示す目印」という一般論を長々と答えた。AIE2026についても「たぶんこういう講座です」と想像で答えていた。本当の意味とは違う。道具がないAIは、講座だけの言葉を知らない。知らないと、想像で埋める。そこがはっきり見えた。
- エージェント（app.agent）：「各回の演習開始時点のコードについているGitのタグ（例：lec03-start）。前の回が終わっていなくても、このタグから新しい枝（ブランチ＝作業用のコピー）を作れば、その回を始められる」。用語集（講座の言葉の辞書）のとおりに、正しく答えた。関係する回も「第1回」で合っていた。
- まとめ：道具があるかないかで、答えの正しさが全然違う。

### --trace で見えたツール呼び出し（ツール名と引数）：

--traceというのは、「AIがどの道具を、どういう注文で使ったか」の記録を出す設定。引数というのは、道具への注文内容のこと。

質問：「LoRAとQLoRAの違いは？」
LoRAとQLoRAは、AIの学習のやり方の名前。第2回で習った。

- 書き換える前：search_glossary（用語集を調べる道具）が2回だけ。LoRAとQLoRAを調べただけ。答えは定義の箇条書きだった。
- INSTRUCTIONS（エージェント全体への指示書＝全体のルール）を書き換えた後：search_glossaryが2回＋get_lecture_summary（その回のまとめを読む道具）が1回。合計3回に増えた。答えも「最初に違いの表、そのあと短い説明」に変わった。
- docstring（道具1つ1つに貼った説明メモ）も書き換えた後：合計3回。変わらなかった。docstringに書いた「関係する用語ももう1回調べる」は、動かなかった。

実際の記録：
- `search_glossary({'query': 'LoRA'})`（query＝調べる言葉）
- `search_glossary({'query': 'QLoRA'})`
- `get_lecture_summary({'lecture': 2})`（書き換えた後だけ。lecture＝第何回）

### 1つの質問での LLM 呼び出し回数（requests）：

- 書き換えた後：3回。記録の[usage]という欄に requests=3 と出た。
- 書き換える前：数字は取れていない。

### 追加したツールと、docstring に書いた説明：

- ツール名：make_quiz（問題を作る道具）。app/tools.pyに作って、app/agent.pyに登録した。
- 仕事：指定した回の用語から1つ選んで、「この用語の意味は？」という問題と答えを返す。
- docstringに書いた内容：「理解度を確認したいとき、復習の問題がほしいときに使う。指定した回の用語から1つ選び、『この用語の意味は？』という問題と答えを返す」
- やってみた：「第2回の内容から確認問題を1問出して」と頼んだ。すると make_quiz（lecture=2）が呼ばれて、「『事前学習』の意味は？」と出た。答えは出てこない。自分で考える形になっていた。AIの呼び出しは2回、道具は1回。

## 宿題

### 取り組んだレベル：発展

発展(a)「Google ADKで作り直す」を選んだ。実装もやった。
Google ADKというのは、Googleのエージェント組み立て道具セット。元の道具セットはPydantic AIという名前。

### やったこと：

- 基礎：全体のルール（INSTRUCTIONS）と道具の説明メモ（docstring）を書き換えて、同じ質問で比べた
- 実装：「学習ログを保存する道具」を作った。保存の前に「保存していいですか？」と利用者に聞く仕組みつき。テストも書いた。テストでは偽物のAI（TestModel＝テスト専用の偽のAI。本物みたいにお金も時間もかからない）を使った
- 発展(a)：ルールと道具はそのまま。組み立て方だけをGoogle ADKに替えて作り直して、同じ質問で比べた

### 結果：

- 基礎：ルールを書き換えたら、道具の呼ばれ方が2回から3回に増えた。答えに「違いの表」もついた。逆に、道具ごとの説明メモを書き換えても、動きは変わらなかった。全体ルールのほうが効き目が強い。
- 実装：保存の道具（save_learning_log）が動いた。「記録して」と頼むと、まず「実行しますか？」と聞かれる。「y」と答えると、learning_logフォルダ（学習ログを入れる場所）のファイルに1行保存された。テストは13個全部合格（pytest＝テストをまとめて実行するコマンドで、13 passedと出た）。
- 発展(a)：ADK版も、元の版とほぼ同じ動きだった。表つきの答えも同じ。ルールと道具は、元のファイルを読み込んで（import＝他のファイルの部品を借りてくること）そのまま使った。本当に同じもの同士で比べられた。
  - 違い1（道具の動きの見え方）：元の版は--traceで動きが文字で全部見える。ADK版は、adk run（文字だけの画面）では答えしか見えない。動きはadk web（ブラウザの画面）で見る作りだった。その画面では、道具の呼び出しが順番つきのチップ（小さな札）で表示された。search_glossary が呼ばれたことと、その結果が返ったことが、答えの上に並んで見えた。答えの中身も、表→説明→「関係する回：第2回」で、元の版と同じだった。なお、adk web の画面は最初は開けなかった。原因は、古いサーバーがポート8000に居座っていて、新しい設定のサーバーが起動できていなかったこと。古いサーバーを全部止めて（pkill）から、許可を広げる設定（--allow_origins "*"）で起動し直したら開けた。
  - 違い2（保存の確認のされ方）：元の版は、自分で書いた確認で「y」で保存された。ADK版は確認の仕組みが最初から用意されていた。でも「yes」と全部打たないと保存されなかった。「y」だけだと断られた。

### 気づき・疑問：

- いちばん苦労したのは、adk web の画面が開かなかったこと。何時間もはまった。許可の設定を変えても、ポートを公開しても、真っ暗なまま。「403＝門番に止められている」と思い込んでいた。でも本当の原因は、もっと手前だった。古いサーバーがポート8000に居座っていて、新しい設定のサーバーが一度も起動できていなかった。サーバーの記録の1行（address already in use＝もう使われている）をちゃんと読んだら、一発で分かった。思い込みで遠回りした。記録は、ちゃんと読むと答えをくれる。これが今回いちばんの教訓だ。
- 苦労したこと2つ目：保存の道具を「確認つき」にしたら、もともとのテストが落ちた。確認待ちの道具は、その場では結果を返さない。だから「呼んだ数と結果の数を比べる」テストと合わなかった。講座の第4回用の新しいテストを見たら、数え方が「結果の数＋確認待ちの数」に直っていた。同じ直し方をしたら、全部合格に戻った。落ちた理由を追うのに時間がかかった。
- 苦労したこと3つ目：消えていた部品探し。第1回の既定の質問（DEFAULT_QUESTION）が app.ask から消えていて、テストが落ちた。自分の今回の変更とは関係ない場所だった。git の履歴を掘ったら、第1回の自分の作業で消えていたと分かった。昔の版から元の文を復元して直した。
- 苦労したこと4つ目：説明メモを手で書き換えたら、行の頭の空白がずれてエラーになった（IndentationError＝空白のずれのエラー）。書き換えもプログラムにやらせる方法に変えて、解決した。
- ルールを書く場所で、効き方が違う。全体ルールは強い。道具ごとのメモは、今回は効かなかった。LoRAとQLoRAはお互いが「関係する用語」で、両方もう調べ終わっていた。だからAIが「もう調べなくていい」と判断したのだと思う。
- 道具がないAIは、知らない言葉を想像で埋めて、もっともらしく答える。知らないのに、知っているみたいに答える。講座みたいに「その場所だけの言葉」が多い相手には、用語集のような道具が本当に大事だ。
- 保存みたいな大事な操作は、勝手にやらせない。「まず聞く」仕組みがいる。作り方は道具セットで違った。元の版は聞き方を自分で書く。ADKは用意されている。
