# 動画配信サブスク 無料トライアル後の継続予測

評価指標: Log Loss（小さいほど良い）

## 実行方法

```bash
cd competitions/subscription_continuation
pip install lightgbm catboost scikit-learn pandas scipy
# input/ に train.csv, test.csv, films.csv, viewing_log.csv, sample_submit.csv を置く（再配布防止のため git 管理外）
python src/train.py                  # → output/submission.csv（ヘッダなし, ID, 確率）
python -m pytest tests -q            # 単体テスト
```

`config/params.json` に Optuna で探索したパラメータが入っている（無ければ既定値で動く）。

## 楽観の検証（`src/nested_check.py`, `src/holdout_check.py`）

| 検証 | 結果 | 結論 |
|---|---|---|
| 選択の楽観: 外側 5 fold で、学習側だけでハイパーパラメータ（Optuna 30試行）・袋 C・特徴量群を選び直した版(A)と、全データで選んだ現行設定(B)を比較（外部予測4本入り） | A 0.2641 / B 0.2673、A−B −0.0032 ± 0.0075 | 楽観は検出されず。C は全 fold で 20 を選択。ただし B は 1 fold で 0.316 と崩れた（正則化が弱く分割に敏感） |
| 評価手順の楽観: 学習データの 20% を擬似 test として取り分け、残りで本番と同じ手順（15 repeat × 3種平均 × ブレンド）を実行（外部予測なし, 5通り） | CV 0.2756 / 擬似 test 0.2719、差 −0.0037 ± 0.0168 | 楽観は検出されず。予測の広がりも OOF と擬似 test で同程度 |

- 擬似 test（284人）の損失は取り分けごとに 0.248〜0.314 と ±0.03 揺れる。公開 LB（約424人）も同程度揺れるため、
  CV 0.2433 → 公開 LB 0.2614 の差は主に公開分の抽出の揺れで説明できる。
- 検出力の限界: 2σ で排除できるのは 選択の楽観 約0.015 以上、手順の楽観 約0.03 以上。外部予測そのものの作り方は検証対象外。

### 小さな楽観の検証と正則化の検討

| 検証 | 結果 | 結論 |
|---|---|---|
| 評価手順（擬似 test の同じ利用者で、CV 方式=15個平均 と test 方式=全モデル平均 を対応比較, 全1,419人） | test 方式 − CV 方式 = −0.0023 ± 0.0016。手元 CV 0.2776 ≒ 擬似 test の CV 方式 0.2772 | CV に楽観なし（わずかに悲観的） |
| 選択の楽観（入れ子, 外側 15 fold を利用者単位で合算） | 入れ子 − 現行 = −0.0101 ± 0.0044 | 楽観なし（現行設定が評価用利用者に有利に働いた形跡なし） |

正則化候補（事前固定）。CV は外部予測4本入り・seed 0〜4・基本クレンジング、擬似 test は外部予測なし・test 方式で現行との対差。

| 候補 | CV（交差フィット） | 1モデル平均 / 最悪 fold | test 広がり | 擬似 test（現行との差） |
|---|---|---|---|---|
| R0 現行（学習量多め・正則化弱め） | **0.2498** | 0.2777 / 0.3288 | 3.63 | — |
| R1 中程度 | 0.2509 | 0.2693 / 0.3284 | 3.45 | — |
| R2 強め | 0.2537 | 0.2665 / 0.3091 | 3.40 | +0.0185 ± 0.0049 |
| R3 入れ子選択の中央値 | 0.2508 | 0.2614 / 0.2972 | 3.45 | +0.0257 ± 0.0055 |

- 正則化を強めると 1 モデル単位の成績と安定性は上がるが、分割を変えた多数平均（本番の形）では現行が最良。
  ばらつきの大きいモデルほど平均（バギング）の効果が大きいため。入れ子検証で 1 モデル単位では現行が不利に見えたのも同じ理由。
- 結論: 現行パラメータを維持。予測の極端さ（test 広がり 3.63）は正則化では CV を落とさずに抑えられない。

基準 B0 = 3種クレンジング × (LightGBM + LR) + 外部予測4本、交差フィット。利用者単位の対差（seed 0〜4 で選別 → seed 5〜14 で確認）。

| 候補 | seed 0〜4 | seed 5〜14（確認） | 判定 |

| C2 シーズン共変量をブレンド校正に追加 | +0.00090 | — | 不採用 |
| C3 LightGBM 3 seed 平均 | −0.00032 ± 0.00028 | +0.00057 ± 0.00023 | 不採用（確認で悪化） |
| C4 CatBoost 追加 | +0.00015 | — | 不採用 |

レポート系列との混合（seed 0〜14 全体, 基準 = 手元 + v52）:

| 構成 | 3種クレンジング | 4種（+本番） |
|---|---|---|
| 手元のみ | 0.24322 | 0.24271 |
| 手元 + v52（fmlmxft） | 0.24157 | **0.24125** |
| 手元 + 使える4系列すべて | 0.24125（−0.0003 ± 0.0005） | 0.24098（−0.0003 ± 0.0004、v52 以外の重みは ≈0） |

- 最終: 4種クレンジング + v52 混合（交差フィット 0.24125）→ `output/submission_final_mix4.csv`。
  前回の混合（公開 LB 0.25566）とロジット相関 0.9999 で、ほぼ同じ予測の小改良。
- 全系列混合は差が SE 以内で、重みが v52 以外ほぼ 0 のため採らない（単純な方を優先）。

- 結論: 残りの改善余地は 0.0005 程度で、検出限界（SE ≈0.0005）に近い。手元で取れる改善はほぼ出尽くした。

## 手法

1. **クレンジング** (`src/clean.py`)
   - タイトルIDの復元: 欠損(約5%)・接頭辞欠落("001")・"movie" を、同一ユーザーの前後レコード → 視聴履歴 → 視聴時間/話数との整合 + 人気 の順で推定。人工的に壊した検証で 数字ID 90% / movie 85% / 完全欠損 49% を復元。
   - 視聴時間: 300 超は秒単位の記録とみなし /60。1話時間の 1.2 倍でクリップ。
   - エピソードNo・デバイス欠損の補完。
2. **特徴量** (`src/features.py`, 約110個)
   - 視聴量・完走率・アクティブ日数・セッション
   - トライアル内の時系列推移（期間別視聴量、日次傾き、後半比率、連続視聴日数、最終視聴から期間終了まで）
   - 作品消化（完走作品数、視聴途中のシリーズ数、週次配信の途中作品、残エピソード数）
   - 週次/独占配信比率、カテゴリ・デバイス構成比、プロフィール数、時間帯・曜日
   - 作品概要の文字 n-gram TF-IDF → SVD をユーザーの視聴時間で加重平均
   - 属性・アンケート（カテゴリ + 順序エンコード）
3. **モデル** (`src/train.py`): 出来事トークン袋モデルの入れ子スコアを加えた LightGBM / ロジスティック回帰（CatBoost は任意）を 5-fold × 10 repeat × 3種クレンジングで学習し、logit 空間で非負重み + バイアスを OOF に最適化してブレンド。最終予測は [0.001, 0.999] にクリップ。

| **+ 復元方法の異なる3種クレンジングの平均（現行）** | **0.2684** |

### 検証レポートを踏まえた検証（LightGBM, 5-fold × 4 repeat, fold 単位の対差）

| 変更 | Δ LogLoss | fold 勝率 | 判定 |
|---|---|---|---|
| 完全重複行の除去（2,670 行 / 50 人） | −0.0069 ± 0.0016 | 85% | 採用 |
| 欠損率など品質列の除外 | +0.0003 ± 0.0012 | 50% | 採用（情報なし・列削減） |
| シーズン進行・週次の追いつき・カテゴリ×独占×週次・時間帯ルーティン・デバイス組合せ | −0.0061 ± 0.0022 | 85% | 採用 |
| 出来事トークン袋モデル（L2 LR, C=20）の入れ子スコアを GBDT 特徴量に | −0.0067 ± 0.0031 | 70% | 採用 |
| 3種クレンジング（full / no_history / neighbor）の logit 平均（ブレンド後, 利用者単位の対差） | −0.0033 ± 0.0020 | — | 採用 |
| 視聴時間の ×10/×60/×100 桁ずれを除数選択で補正（従来はクリップのみ） | （重複除去と同時に導入） | — | 採用 |

未実施: TabPFN / TabFM / LimiX-2 / FTFM-1 など事前学習モデルの入れ子予測（レポートで最大の上積み）。

### 独自の検証

| 検証 | 結果 | 判定 |
|---|---|---|
| ブレンド重み・校正を同じ OOF で決める楽観（5分割の交差フィットで測定） | +0.0020 ± 0.0010（正直な見積もりは 0.2704） | `train.py` が交差フィット値も出力 |
| LightGBM `extra_trees` | fold 単位では −0.0113 ± 0.0026 だが、最終形（10 repeat × 3種平均）では ±0（0.27040 → 0.27047） | 不採用 |
| 単調性制約（視聴日数・デバイス数など10列） | −0.0007 ± 0.0009 | 不採用 |
| ラベル不要の代理タスク（前半の行動から後半の視聴を予測し「予想外れ」を特徴量に。test のログも学習に使用） | +0.0019 ± 0.0012（悪化） | 不採用 |

教訓: 分散を下げる工夫は、多数平均の最終形で評価しないと効果を過大に見積もる。

不採用: 作品ターゲットエンコーディング（LOO はリークで 0.419、内側 K-fold でも 0.312 と改善なし）、ユーザー×作品行列 SVD（0.314）。
