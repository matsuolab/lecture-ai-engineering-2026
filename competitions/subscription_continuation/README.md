# 動画配信サブスク 無料トライアル後の継続予測

評価指標: Log Loss（小さいほど良い）

## 実行方法

```bash
cd competitions/subscription_continuation
pip install lightgbm catboost scikit-learn pandas scipy
# input/ に train.csv, test.csv, films.csv, viewing_log.csv, sample_submit.csv を置く（再配布防止のため git 管理外）
python src/train.py                  # → output/submission.csv（ヘッダなし, ID, 確率）
python -m pytest tests -q            # 単体テスト
```

`config/params.json` に Optuna で探索したパラメータが入っている（無ければ既定値で動く）。

| + TabPFN-mix・TabFM の入れ子予測 | 0.24813 | 0.25022 | `output/submission_ext2_backup.csv`（保険） |
| + LimiX-2・FTFM-1 も追加（4本） | 0.24122 | 0.24332 | `output/submission_ext4_main.csv`（本命） |

- 外部の入れ子予測は検証レポートのパイプラインが Colab（GPU）で計算したもの（`external/*.npz`, git 管理外）。
  分割が手元の `StratifiedKFold(5, shuffle=True, random_state=s)` と全 75 fold で一致することを読み込み時に検証している。
  実行: `python src/train.py --ext tabpfn,tabfm,limix,ftfm --out output/ext4`
- 公開 LB（2026-11-23）: 本命 ext4 0.26142 / 保険 ext2 0.26391（レポート v52 は 0.25398）。
  CV→LB の絶対差 +0.018 は公開分（約424人）の標準誤差 ≈0.026 の範囲。ただし v52 との差は OOF 見込み −0.0045 に対し LB +0.0074（対差の SE≈0.0072, 約1.65σ）。

- 対策案: 手元版と v52（`series_logits.npz` の fmlmxft 系列）を OOF で重み付けして混合 → 交差フィット 0.2412
  （手元 0.2433 / v52 0.2472）。`output/submission_ext4_x_v52.csv`（重み 手元0.64 : v52 0.32）。
- 本命 4 本版の test 予測は、レポートの v52（公開 LB 0.25398）とロジット相関 0.979。
- LimiX-2・FTFM-1（と TabFM）の重みは非商用ライセンス。提出前にコンペ規約で使用可否の確認が必要。

## 手法

1. **クレンジング** (`src/clean.py`)
   - タイトルIDの復元: 欠損(約5%)・接頭辞欠落("001")・"movie" を、同一ユーザーの前後レコード → 視聴履歴 → 視聴時間/話数との整合 + 人気 の順で推定。人工的に壊した検証で 数字ID 90% / movie 85% / 完全欠損 49% を復元。
   - 視聴時間: 300 超は秒単位の記録とみなし /60。1話時間の 1.2 倍でクリップ。
   - エピソードNo・デバイス欠損の補完。
2. **特徴量** (`src/features.py`, 約110個)
   - 視聴量・完走率・アクティブ日数・セッション
   - トライアル内の時系列推移（期間別視聴量、日次傾き、後半比率、連続視聴日数、最終視聴から期間終了まで）
   - 作品消化（完走作品数、視聴途中のシリーズ数、週次配信の途中作品、残エピソード数）
   - 週次/独占配信比率、カテゴリ・デバイス構成比、プロフィール数、時間帯・曜日
   - 作品概要の文字 n-gram TF-IDF → SVD をユーザーの視聴時間で加重平均
   - 属性・アンケート（カテゴリ + 順序エンコード）
3. **モデル** (`src/train.py`): 出来事トークン袋モデルの入れ子スコアを加えた LightGBM / ロジスティック回帰（CatBoost は任意）を 5-fold × 10 repeat × 3種クレンジングで学習し、logit 空間で非負重み + バイアスを OOF に最適化してブレンド。最終予測は [0.001, 0.999] にクリップ。

### 検証レポートを踏まえた検証（LightGBM, 5-fold × 4 repeat, fold 単位の対差）

| 変更 | Δ LogLoss | fold 勝率 | 判定 |
|---|---|---|---|
| 完全重複行の除去（2,670 行 / 50 人） | −0.0069 ± 0.0016 | 85% | 採用 |
| 欠損率など品質列の除外 | +0.0003 ± 0.0012 | 50% | 採用（情報なし・列削減） |
| シーズン進行・週次の追いつき・カテゴリ×独占×週次・時間帯ルーティン・デバイス組合せ | −0.0061 ± 0.0022 | 85% | 採用 |
| 出来事トークン袋モデル（L2 LR, C=20）の入れ子スコアを GBDT 特徴量に | −0.0067 ± 0.0031 | 70% | 採用 |
| 3種クレンジング（full / no_history / neighbor）の logit 平均（ブレンド後, 利用者単位の対差） | −0.0033 ± 0.0020 | — | 採用 |
| 視聴時間の ×10/×60/×100 桁ずれを除数選択で補正（従来はクリップのみ） | （重複除去と同時に導入） | — | 採用 |

未実施: TabPFN / TabFM / LimiX-2 / FTFM-1 など事前学習モデルの入れ子予測（レポートで最大の上積み）。
本環境から Hugging Face に接続できず重みを取得できないため。重みの多くは非商用ライセンスで、コンペ規約の確認も要る。

### 独自の検証

| 検証 | 結果 | 判定 |
|---|---|---|
| ブレンド重み・校正を同じ OOF で決める楽観（5分割の交差フィットで測定） | +0.0020 ± 0.0010（正直な見積もりは 0.2704） | `train.py` が交差フィット値も出力 |
| LightGBM `extra_trees` | fold 単位では −0.0113 ± 0.0026 だが、最終形（10 repeat × 3種平均）では ±0（0.27040 → 0.27047） | 不採用 |
| 単調性制約（視聴日数・デバイス数など10列） | −0.0007 ± 0.0009 | 不採用 |
| ラベル不要の代理タスク（前半の行動から後半の視聴を予測し「予想外れ」を特徴量に。test のログも学習に使用） | +0.0019 ± 0.0012（悪化） | 不採用 |

教訓: 分散を下げる工夫は、多数平均の最終形で評価しないと効果を過大に見積もる。

不採用: 作品ターゲットエンコーディング（LOO はリークで 0.419、内側 K-fold でも 0.312 と改善なし）、ユーザー×作品行列 SVD（0.314）。
