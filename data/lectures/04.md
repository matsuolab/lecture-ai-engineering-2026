# Lecture 04 Evaluation (Evaluation Sets and LLM-as-a-Judge)

## Aims

- Measure whether a system works well using an evaluation set and criteria, rather than intuition
- When using an LLM to grade answers, check whether its grading is trustworthy by measuring agreement with human judgments

## Key Points

1. **Evaluation set**: A collection of inputs and expected outputs or conditions for passing. Deliberately include inputs likely to cause failures (edge cases), as well as normal cases.
2. **Evaluation criteria (rubric)**: Define pass/fail conditions in writing for each criterion. Requirements in the agent's instructions (INSTRUCTIONS) can directly become criteria.
3. **Designing the scale**: T/F judgments for each criterion make it easier than numeric scores to count how many judgments differ and on which criteria. Derive the overall result mechanically from the criteria.
4. **LLM-as-a-Judge**: Have an LLM grade answers using a rubric. It is inexpensive and fast, but the grader's biases, such as preferring verbose answers or being influenced by order, affect the results.
5. **Calibrate through agreement**: Check agreement between human labels and LLM judgments before relying on the grader. Humans also disagree on subjective criteria, so the attainable agreement rate is not 100%.
6. **Send unresolved items to humans**: Mark items that divide opinions because the rubric has no policy as unsure, exclude them from automatic decisions, and send them for human review. Deciding the policy and adding it to the rubric is the evaluation designer's job.
7. **Use code where code can judge**: Check formatting, such as a final "Lecture N" marker, deterministically with code rather than asking an LLM.

## What You Will Try in the Exercises

- Label ten evaluation cases yourself
- Have an LLM grade the same ten cases and read its agreement with your labels
- Decide a policy for an item needing review, add it to the rubric, and check how the judgment changes
