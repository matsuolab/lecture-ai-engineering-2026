# Lecture 06 External Tools and MCP

## Aims

- Understand how to extract agent tools from functions inside an application into "external services"
- Experience how MCP (Model Context Protocol) lets tools be shared across clients

## Key Points

1. **External tools**: Capabilities outside the agent, such as web retrieval, file operations, databases, and third-party APIs. Lecture 03's function tools ran in the same process; external tools are called across processes or machines.
2. **Role of MCP**: A common protocol between the provider of tools (MCP server) and the user of tools (MCP client, such as an agent or editor). Build one server and use it the same way from any compatible client.
3. **What a server exposes**: Tool names, descriptions, and argument schemas. The model reads these to decide which calls to make. The same information as Lecture 03's docstrings arrives from outside the process.
4. **Transport**: With stdio, the client starts the server as a subprocess and exchanges data through standard input/output. With Streamable HTTP, the server listens at a URL and can accept connections from other machines.
5. **Ready-made servers**: Public servers for file operations, web retrieval (fetch), GitHub, and more can be used simply by adding them to a configuration file (mcpServers format). Users are responsible for what they allow (file writes, sending data externally).
6. **Namespaces and cost**: Tools from different servers are distinguished as "server_name_tool_name". More tools mean more descriptions sent to the model, affecting tool-selection accuracy and tokens per call.
7. **Safety**: MCP servers execute arbitrary code. Do not configure servers from unknown sources. When exposing a server over HTTP, consider authentication and access scope (Codespaces port forwarding is private by default).
